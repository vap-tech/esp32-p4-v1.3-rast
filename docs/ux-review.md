## Визуальная структура: что улучшить первым

1. **Файлы — основной рабочий экран.** На телефоне360×800 список начинается наy≈637.
   Компактнее шапка и toolbar, одна заметная загрузка; вторичные действия сгруппированы.
   Подготовка JPEG относится к загрузке, фоторамка — к выбранной папке, управление
   устройством — к отдельному блоку. Статус остановленной фоторамки сейчас постоянно
   занимает место перед таблицей, хотя не требует действия.
2. **Читаемость важнее бледных подписей.** Основной текст на телефоне можно увеличить
   до16px, служебный держать12–13px с достаточным контрастом. Для desktop допустима
   более плотная таблица. Данные выравнивать и использовать tabular-nums для размеров.
3. **Таблица с реальными данными.** Убрать пустую колонку даты до появления backend-дат,
   отдать место имени; сохранить существующие44px-меню действий. Для больших каталогов
   полезны локальный поиск по именам и сортировка, без новой библиотеки/запроса на каждую букву.
4. **Единые состояния операций.** Ожидание, ошибка и успех должны различаться текстом,
   формой и доступным объявлением. Текущий статус удаления и различие передачи100%/
   сохранения на SD сохраняются. Подготовка фото, ошибка каталога и история ошибок партии
   требуют доработки по замечаниям ниже.
5. **Лёгкая визуальная система.** Нейтральные поверхности, один акцент для основного
   действия, отдельные семантические цвета ошибок/успеха, согласованные отступы и иконки.
   Цвет связи должен отражать проверенное состояние: зелёная точка LAN/HTTP сейчас
   задана CSS постоянно (`index.html:36`), это декоративная метка, а не проверка соединения.

## Приоритетные замечания

### 1. P1 — Загрузка папки недоступна с клавиатуры

`frontend/index.html:187` — видимая «Загрузить папку» является label без tabstop,
а связанный input имеет hidden. Tab пропускает действие целиком. У обычной
загрузки input попадает в Tab, но имеет opacity0 и размер1×1, так что фокус
невидим на видимой кнопке (`index.html:63`, `index.html:183`).

Исправление: настоящие button для обоих действий с открытием соответствующего
file input; видимый focus на самих кнопках. В проверенной последовательности
Tab folderpicker отсутствовал, picker имел opacity0 и размер1×1.

### 2. P1 — Ошибка чтения выдаётся за пустую папку

`frontend/index.html:352` — catch вызывает render([]): одновременно показаны
«Не удалось получить список: HTTP404» и «Папка пуста. Загрузите сюда первый файл».
Пользователь получает противоречивое описание содержимого карты.

Исправление: отдельные loading/empty/error/success-состояния. Ошибка не должна
рисовать empty-state или подтверждать нулевое число элементов. Дать повторить
запрос; при сохранении старого списка явно обозначить его неактуальность.
В Chromium воспроизведено переходом в отсутствующую папку /MISSING.

### 3. P2 — После перехода в папку теряется фокус

`frontend/index.html:304` — replaceChildren уничтожает сфокусированную кнопку
папки; после успешного go('/DOCS') activeElement=BODY. Следующий Tab начинает
обход с верхних элементов, вместо продолжения работы в открытом каталоге.

Исправление: после навигации переводить фокус на заголовок/путь нового каталога,
после обновления того же каталога сохранять фокус по стабильному имени/действию.
Это также касается перерисовки после удаления/переименования. Не перехватывать
фокус на каждом фоновом обновлении статуса.

### 4. P2 — Длинные пути обрезаются вместе со статусом удаления

`frontend/index.html:50` — у breadcrumb-кнопки нет ограничения/переноса длинного
неразрывного имени. На360px её правый край1622px, край панели348px. overflow:hidden
панели скрывает часть пути. `index.html:198` и `index.html:558` — статус удаления
тоже не имеет overflow-wrap; длинное имя уходит за границу и обрезается.

Исправление: ограничить breadcrumb-элементы по доступной ширине с управляемым
сокращением и возможностью прочитать полный путь. Для текста операций использовать
перенос длинных имён (overflow-wrap:anywhere), не скрывать важную часть имени.

### 5. P2 — Недостаточный контраст вторичного текста в светлой теме

`frontend/index.html:70` — заголовки колонок #8b97aa на #f9fafd:2,83:1,
при10px это обычный мелкий текст, не large text. `index.html:86` — метаданные
#738097 на белом:3,99:1. `index.html:10` — --muted на белом:4,02:1;
`index.html:110` — footnote на основном фоне:2,35:1.

Исправление: усилить цвет важных подписей/размеров/статусов до4,5:1 на фактическом
фоне. Проверять темы отдельно. Числа получены расчётом относительной sRGB-яркости.

### 6. P2 — Подготовка следующего фото сохраняет заполненную полосу предыдущего

`frontend/index.html:470` — preparePhoto очищает проценты/скорость, но не сбрасывает
upload-progress. Воспроизведено: имя next.jpg, фаза «Подготовка фото на компьютере…»,
progress.value=100. Это зрительно похоже на готовый или уже переданный новый файл.

Исправление: отдельное неопределённое состояние подготовки (без value у progress)
или скрытая полоса до sendUpload; одновременно сбросить метрики предыдущего файла.

### 7. P2 — В массовой загрузке теряются причины отдельных отказов

`frontend/index.html:530` — сохраняется только lastError, итог показывает число
ошибок и последнее сообщение. Если из200фото не загрузились5, понять полный список
и повторить только неудавшиеся нельзя.

Исправление: компактный список ошибок с именами и краткими причинами; успешные
файлы не заставлять выбирать повторно. Хранить это в браузере, не наращивать SRAM платы.

## Компоновка и второстепенные замечания

- `index.html:181` — на360×800 список начинается наy≈637: toolbar, подготовка фото
  и постоянный статус остановленной фоторамки занимают большую часть первого экрана.
  Основную загрузку/создание оставить заметными, вторичные действия компактнее;
  настройки фоторамки/подготовки группировать по смыслу, список поднять выше.
- `index.html:207`, `index.html:332` — колонка «Изменён» всегда показывает прочерк:
  backend сейчас возвращает только name/dir/size (`src/web/asyncfs.rs:167`). Она
  забирает170px, которые нужны длинным именам; скрыть до появления реальных дат.
- `index.html:322`, `index.html:295` — каталоги и breadcrumbs используют button/go
  вместо ссылок: нельзя штатно открыть папку Ctrl/Cmd+click или средней кнопкой.
  URL уже хранит path, поэтому можно сохранить перехват обычного клика и дать href.
- `index.html:550` — повторное действие во время удаления получает текст про очередь
  загрузки. Сообщение должно соответствовать реально выполняемой операции.
- `index.html:201` — прогресс стоит связать с текущим именем/фазой через доступное
  описание, а не только общим «Передано файла». Табличным данным не хватает
  семантической связи столбцов с ячейками; role=list не передаёт заголовки колонок.

## Что уже работает хорошо

- Путь хранится в URL, работает popstate.
- Удаление подтверждается, есть отдельный статус ожидания и честное подтверждение
  после HTTP-ответа; часы/сервер не объявляются остановленными из-за удаления.
- Upload различает передачу100% и сохранение на SD; есть скорость, очередь и отмена.
- Нативный dialog фоторамки получает начальный focus, есть подписи и fieldset.
- Кнопки ⋮ имеют доступные имена, декоративные file icons скрыты от accessibility tree.
- Обычный мобильный экран не имеет горизонтальной прокрутки; браузерные runtime
  exceptions в проверенных сценариях не обнаружены. Длинный путь именно обрезан,
  а не создаёт горизонтальный скролл всей страницы.
- Формат JPEG и подготовка остаются на компьютере, без библиотек/CDN.

Предлагаемый порядок: клавиатура → error-state → focus/длинные пути → контраст и
прогресс → компоновка/история ошибок. Это улучшения интерфейса, изменения backend
для первых пунктов не требуются.
