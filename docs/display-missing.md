## Схемы I_W и I_W_Y различаются

В открытой копии исходного пакета Guition найдены семь листов схемы
[JC1060P470C_I_W](https://github.com/cheops/JC1060P470C_I_W/tree/main/5-Schematic):
питание, LCD, P4, разъёмы, C6, USB, codec. Это изображения схем, а не
пересказ README. [LCD-лист](https://raw.githubusercontent.com/cheops/JC1060P470C_I_W/main/5-Schematic/2_LCD.png)
показывает GPIO27 LCD_RST, LCD_PWM, STBYB и пары DSI. На LCD FPC отдельные
TE/BIST_EN не указаны. [Лист P4](https://raw.githubusercontent.com/cheops/JC1060P470C_I_W/main/5-Schematic/3_ESP32-P4.png)
показывает PA_CTRL=GPIO20, TOUCH_INT=GPIO21, TOUCH_RST=GPIO22, LCD_PWM=GPIO23.
Совпадение GPIO27/23 и PA20 делает эту схему более близкой к сохранённому
voice-проекту, но точная маркировка нашей PCB ещё не сообщена.

Найдена также [схема JC1060P470C_I_W_Y-V1.0](https://github.com/wegi1/ESP32P4-JC1060P470C-I_W_Y/blob/main/5-Schematic/JC1060P470C_I_W_Y-V1.0.pdf).
Там LCD_RST подключён к GPIO0. Значит, похожее название платы не гарантирует
совпадения GPIO. Переносить назначения I_W_Y в наш HAL по этому PDF нельзя
без сопоставления PCB. Firmware пока использует прежние GPIO27/23.

Нумерация FPC на схеме I_W и в PDF модуля дана противоположно: например,
RESET — контакт 4 символа схемы и 27 в модульном PDF, LED+ — 30/29 против
1/2. Это не подтверждённая прозвонкой карта шлейфа; считать номера из двух
документов взаимозаменяемыми нельзя. Нет отдельного выведенного TE на
рассмотренном FPC, даже если команда TEON принимается контроллером.

## Конкретная зацепка BIST: первичный экспериментальный отчёт

Автор исходного [отчёта о запуске JD9165 на Raspberry Pi](https://forums.raspberrypi.com/viewtopic.php?p=2318521)
публикует свой init и сообщает, что BIST работает. В его комментариях для
BIST указаны значения на page 1:

- select page: `0x30=0x01`;
- `0x05=0x01`;
- `0x06=0x40`.

Это первичный отчёт автора эксперимента с другой платой, **не подтверждённая
карта BA-регистров**. У нашей проверенной vendor-таблицы оба регистра имеют
значение 00. Роли отдельных битов, допустимые комбинации, выбор паттернов и
способ корректного выхода полностью не установлены.

Дальнейший ограниченный эксперимент можно сделать отдельно: сохранить
обычный режим, выбрать page 1, записать эту пару, вернуть page 0, проверить
видимую картинку при остановленном видеопотоке P4 и восстановить панель
через hardware reset + проверенный init. Без визуальной проверки режима
при остановленном TX нельзя считать BIST подтверждённым. Пара пока не является подтверждённой функцией панели; ограниченный
экспериментальный helper описан ниже.

## Что осталось не найдено

- Полный register/programming manual именно JD9165BA-DS.
- Подтверждённый способ вывода TE на доступный контакт нашего экземпляра.
- Объяснение некорректной ECC ответа BA на DCS45h.

В новом vendor-примере I_W_Y есть `te_on()`/`te_off()` через обычные DCS35h/34h,
но нет подтверждения физической разводки TE или BIST API. Исходник OpenLuat
для RGB-панели JD9165BA не содержит register init: там конфигурация выполнена
аппаратными strap-пинами; к нашему MIPI-режиму это не переносилось.
Оригинальная публичная ссылка архива производителя сейчас возвращает HTML
вместо ZIP, поэтому для схем использованы открытые копии исходного пакета.

## Ограниченная аппаратная проба BIST

По запросу пользователя добавлена `Display::probe_panel_bist(timer)` и
USB-команда `B`. Проба останавливает video mode P4, пишет на page 1
05=01/06=40, возвращает page 0 и ждёт 25 секунд. Затем независимо от
успеха экспериментальных записей пытается выполнить аппаратный reset
и проверенный init, восстановить пользовательские настройки. Для init
теперь явно выбирается page 0 перед чтением ID, в том числе после ошибки
эксперимента на vendor page.

Во время окна нет USB-записей, поэтому нечитающая консоль не мешает таймеру
и восстановлению. После завершения выдаются `BIST_RESULT` со статусом host
внутри окна и `BIST_RESTORED` с обычным статусом панели. Яркость остаётся
5%. Команда Linux: `python scripts/display-control.py B q e`; таймаут
ожидания результата B увеличен до 40 секунд.

Результат требует визуальной оценки: несколько сменяющихся тестовых
картинок при `video_enabled=false` подтверждают генератор панели;
неподвижная картинка сама по себе не доказывает BIST. Лог пробы:
`target/display-bist-probe.log`.

Первая аппаратная проба 2026-11-05: `video_enabled=false`, PHY=15BDh
(lock и stop state clock/data lanes), TX FIFO пуст, errors0/1=0; окно
25000002 мкс. Автовосстановление дало video=true, duty=51, power=14h,
BER first pixel `[AA,AA,AA]`, счётчик ошибок приёмника=0. Машинная проверка:
`target/display-bist-check.json`. Пользователь визуально подтвердил цветные полосы, шахматку, градиенты,
цветные заливки, область темнее окружающего фона и краткое погасание.
При остановленном video P4 это **подтверждает автономный BIST панели**
для пары page1 05=01/06=40 на данном экземпляре. Яркость во время окна
не менялась: GPIO23 продолжал PWM 20 кГц, duty=51 (5%). Чёрный кадр
или погасание сами по себе не доказывают переход панели в sleep; при
автовосстановлении подсветка также кратко выключается драйвером.

Итог: рецепт включения автономного BIST на этой панели подтверждён
записью регистров, остановкой TX и наблюдением пользователя. Значения
отдельных битов, ручной выбор конкретного паттерна и выход без reset
по-прежнему не установлены; полного programming manual BA нет.
