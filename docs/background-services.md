# Часы, тач и будильник во время Ethernet web-run

Проводной веб больше не останавливает обслуживание RTC и экранных часов.
`src/background.rs` содержит общий обработчик Ui: обычный main loop и web-run
используют один код опроса RTC, отрисовки и тача. Шина I²C и единственный SYSTIMER
заимствуются последовательно, без ISR-доступа к ФС, второго потока или async runtime.

## Планирование

- RTC опрашивается раз в секунду; один снимок используется для AF/AIE и календаря.
- ClockFace рисует только изменившиеся символы, если часы включены.
- GT911 опрашивается раз в 20 мс, события проходят через прежний Tracker.
- При usable + AF + AIE появляется STOP и включаются часы.
- STOP сначала вызывает RX8025T acknowledge_alarm. После успешной записи AF
  снимается, AIE сохраняется, кнопка скрывается и аудио останавливается.
- Пока web-run владеет картой, `Network::tick` выполняет обработчик во время
  обычного обслуживания сети и через idle callback ожиданий SD/Ethernet.
  `Services` не обращается к SD и не запускает вложенный runtime::run.
- Аудио обслуживается до и после Ui, чтобы RTC/отрисовка не откладывали готовый refill.

Обработчик кооперативный: I²C и рисование ещё синхронные, жёстких гарантий real-time
нет. Полная перерисовка часов после invalidate на этой плате заняла до 30,835 мс.
Блокирующий код, который не вызывает Network::tick, сам по себе не становится
неблокирующим. Подключение выполнено для штатного проводного web-run; optional
Wi-Fi и диагностический сервер пока передают Services=None и аппаратно здесь не проверялись.

## Аудио: намеренно кеш целой мелодии

Прежний sd_audio имеет свой блокирующий цикл и свой SD/FAT owner. Вызывать его
из веба нельзя. Новый `src/web_server/alarm_audio.rs` перед WEB READY открывает
`/SATIE.WAV` через общую FileTable, копирует его в PSRAM и закрывает файл.

Текущий файл: 5874912 байт, PCM16 mono 16000 Hz, 5874834 байта сэмплов.
Резерв кеша — размер файла + 128 байт guards; CPU workspace — 2048 байт SRAM.
Фиксированные I2S DMA-данные — прежние 4×2048 байт SRAM, дескрипторы прежние.
Большой PSRAM-регион инициализируется `Arena::allocate_paced`: 64-байтовые пачки
с паузой 320 тактов при CPU160MHz, как при копировании кадров/сетевых данных,
чтобы не забивать PSRAM записями CPU при работающем LCD.

При AF аппаратное кольцо примируется, I2S запускается, снимается mute ES8311
и открывается PA. Громкость прежняя, -21 dB. Mono дублируется в два PCM16 слота;
поддерживается и PCM16 stereo, частота пока строго 16000 Hz. PCM Cursor зацикливает
источник без добавления нулевого хвоста. Во время звучания нет новых аллокаций,
обращений к ФС и операций SD. CPU только формирует очередные 512 packed frames
и возвращает освобождённый блок DMA. Поэтому загрузки на карту не требуют
второго контроллера или конкурентных владельцев FAT.

Это первый этап, не потоковое аудио с SD. Кеш ограничен 8 МиБ; отсутствующий,
занятый или неподдерживаемый SATIE.WAV даёт WEB ALARM UNAVAILABLE, веб и UI
продолжают работу. При повреждённом/poisoned томе веб завершается с ошибкой.
Замена SATIE.WAV во время сессии не меняет звучащий кеш: новый файл подхватится
при следующем web-run. Подготовка кеша добавляет задержку старта; WEB READY
печатается после подготовки. Остановка/deadline во время загрузки кеша
завершает текущую файловую операцию и закрывает handle, не публикуя готовность.

При underrun/DMA error PA выключается и канал останавливается; активный RTC
будильник допускает повторную попытку через 5 секунд. Ошибка не маскируется
повторением старого PCM. На завершении сервера Player останавливает DMA перед
освобождением кеша; если аппаратный парк/сброс DMA не подтверждён, выполнение
останавливается с PA=off. При неожиданном Drop PA закрывается и запрашивается stop.
Main сбрасывает SRAM/PSRAM-арены после возврата, источник DMA — статическая SRAM,
не временный PSRAM/CPU workspace.

Выход из web-run сам по себе не подтверждает RTC AF: если будильник ещё активен,
обычный main продолжит его прежним standalone проигрывателем. Для снятия нужны
STOP либо явный RTC alarm-ack.

## Консоль в активном web-run

Сохраняются framed команды, без переключения дисплея одиночными символами:

```text
:help
:rtc read
:rtc alarm HH MM
:rtc alarm-ack
:rtc alarm-off
:display clock on
:display clock off
:system services
```

RTC-команды используют тот же rtc_command, что обычная консоль. ESC завершает
сервер; прочие команды, требующие эксклюзивного оборудования, отклоняются.
`system services` показывает счётчики Ui и Player. Должен оставаться один USB
читатель; при работающем display-control.py команды отправляются write-only,
ответы читаются из его лога, а не вторым одновременным serial-reader.

`BACKGROUND UI`: RTC reads/errors, число отрисовок/символов, тач-опросы, max gap
и max work. Метрики Ui для рабочей сессии обнуляются после подготовки кеша.
`WEB ALARM SUMMARY`: starts/refills, подготовленные циклы PCM, min_owned,
max_poll_gap_us, max_refill_us, errors/underruns и guards.
min_owned — наблюдаемое число блоков с OWN=DMA, включая текущий. Это не число
полностью готовых блоков и не точная длительность запаса: текущий блок частично
потреблён. max_poll_gap — интервал вызовов, не точное время освобождения дескриптора.

## Проверка на ESP32-P4 rev1.3 — 2026-11-14

I-cache ON, D-cache OFF, L2=0, uncached PSRAM, CPU160MHz.

1. Во время PUT 128 МиБ RTC AF сработал, появился STOP, началась мелодия.
   Пользователь подтвердил ход часов, ровное звучание и отключение по экранной STOP.
2. Лог: touch Down x=534 y=526 → ALARM ACK → I2S stop/mute Ok. После этого
   RTC AF=false, AIE=true, VLF/VDET=false. Передача файла продолжалась.
3. Первый запуск: 1302 refill, min_owned=3, max_poll_gap=8796 мкс,
   max_refill=1383 мкс, errors=0, underruns=0, guards=true.
4. PUT 128 МиБ: 50,809 с = 2,519 МиБ/с; GET: 36,221 с = 3,534 МиБ/с.
   Содержимое сравнено побайтово/SHA256, файл удалён, root неизменён.
5. Второй RTC будильник без перезапуска веба также зазвучал. Подтверждение через
   RTC alarm-ack остановило I2S; суммарно starts=2, refills=1923, errors=0,
   underruns=0, min_owned=3. Исходная настройка alarm 16:32 UTC/AIE=true восстановлена.
6. В длительной сессии 640 успешных чтений RTC и 630 отрисовок; RTC errors=0.
   Max Ui work=30835 мкс (полная перерисовка по clock on). Во время звучания
   максимальный наблюдавшийся интервал аудиообслуживания был 8796 мкс.
7. После штатного выхода стек 55892/65536, guard_ok=true.

Цифровой захват всей I2S-последовательности для этой нагрузки не выполнялся;
поэтому отсутствие пропущенных сэмплов не утверждается только по DMA-флагам.
Есть пользовательское подтверждение звука, аппаратные OWN/ошибки и чистый файл.
Хостовые тесты PCM покрывают mono/stereo порядок, wrap без нулевых вставок,
продолжение курсора и неверное выравнивание; paced allocation проверена по границам.

Финальная сборка: 99 хостовых тестов и all-features Clippy прошли. Короткий
web-run с deadline во время подготовки кеша завершился WEB START CANCELLED/Ok,
все арены used=0, guard_ok=true; новый web-run после этого запустился успешно.
Контрольный 8-МиБ PUT/GET итоговой сборки: 2,474/3,479 МиБ/с, точное совпадение
и cleanup. В рабочем вебе проверены обычная SD-страница и /flash. Счётчики
итоговой сессии: 206 RTC reads, 205 clock draws, 229 изменённых glyphs, RTC errors=0.
Рабочая SRAM capacity 173504 байта; источник+workspace занимают SRAM 2048 байт
и PSRAM 5875040 байт, отдельно от HTTP scratch и колец. После длинного теста
working/DMA/external used=0, high_water соответственно 10240/109440/5940736.
Логи, скрипты и JSON: target/background-services/ (ignored).

Постоянный режим и последующая ручная выгрузка кешей описаны в
[web-lifecycle.md](web-lifecycle.md). После явного GC мелодия загружается при
следующем AF, большой allocator периодически вызывает housekeeping, а PCM
workspace переиспользуется. Для срока жизни веба DHCP lease больше не таймер.
