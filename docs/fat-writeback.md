# Ограниченный кеш FAT и flush — 2026-11-14

Результат [профилирования HTTP](http-upload-profile.md): немедленная запись
каждых четырёх изменённых байт FAT порождала тысячи секторных операций.
Реализован отдельный кеш4 физических FAT-секторов (2048B данных плюс теги)
на Stream/том, общий для всех FileTable handles. Он находится во внутренней
RAM; существующие два partial-sector write-through буфера сохранены.
Данные файлов продолжают идти PSRAM → SD DMA по32KiB.

## Admission и когерентность

FileSystem::fat_region_bytes возвращает byte range всех FAT-копий из уже
проверенного BPB. Cache не угадывает FAT по адресам конкретной карты и
учитывает размер сектора BPB. Сохранён512-Б физический блок нашего адаптера.
Работает с FAT12/16/32, включая переход FAT12-entry через границу сектора.

Только FileTable::write и Volume::Writer::write открывают FatWriteScope.
В этом scope изменения FAT остаются dirty в RAM, данные файла уходят на
носитель сразу. По окончании, ошибке или отмене scope сбрасывает режим admission.
Каждое чтение FAT, в том числе полного сектора, видит актуальный кеш. Большой
read/write через границу FAT режется на границе, поэтому прямой I/O не обходит
грязные строки. Остальные метаданные сохраняют write-through.

## Барьеры сохранения

- flush_fat().await записывает все грязные физические FAT-секторы и вызывает
  device.sync. Dirty-флаги снимаются только после успеха всей операции.
- Вытеснение грязной строки сначала сохраняет всю текущую dirty-эпоху,
  включая изменённые копии. Неудача не разрешает перезаписать строку.
- При записи вне scope Stream сначала flush_fat, затем выполняет write-through.
  Это барьер перед публикацией каталога, FSInfo, boot dirty/clean-marker.
- Stream::flush сбрасывает FAT и синхронизирует устройство. into_inner требует
  отсутствия dirty FAT вместо молчаливого извлечения устройства.
- FileTable sync/close/abort и Writer finish/abort явно сбрасывают FAT перед
  публикацией FileContext (первый кластер/длина). После этого штатный checkpoint
  сохраняет FSInfo; clean-marker снимается только при отсутствии других writers.
- При sync открытого writer том остаётся dirty. Частичные данные ещё могут
  находиться в HTTP PSRAM-очереди: FileTable о ней не знает. HTTP сначала дописывает
  очередь и только затем вызывает close/checkpoint и отвечает201.
- Удаление, mkdir, rename и освобождение кластеров при abort остаются
  write-through; перед их физическими изменениями накопленная FAT сохраняется.
  Скорость отмены большого файла этим изменением отдельно не оптимизировалась.

Периодического фонового flush пока нет. FileTable операции сериализованы,
поэтому изменять содержимое строки во время её DMA flush другой writer не может.

## Ошибки и отмена

После неудачного/отменённого flush все dirty-флаги текущей эпохи остаются
установленными, даже если некоторые сектора уже дошли до карты. Отдельный
fat_flush_incomplete latch запрещает дальнейшие операции Volume; он покрывает
и flush при вытеснении во время чтения, где раньше I/O был только чтением.
Исходный Mutation guard также сохраняет poisoned для неудачной операции.
Низкоуровневый повтор flush способен повторно записать эпоху, но fault-latch
остаётся установленным и не разрешает возобновить работу старого тома; файловый сервис
после ошибки не продолжает обычные записи, требуется восстановление состояния.
Request::Drop сначала останавливает DMA, затем освобождается borrow строки.

Это не журнал и не атомарная транзакция FAT32. Питание между записями двух
копий/страниц FAT может оставить orphan/незавершённую цепочку; dirty-marker
должен сохраниться, автоматическое восстановление пока не реализовано.
На этапе публикации каталога цепочка и обе нужные копии уже сохранены.

## Проверки

94 host-теста: объединение обновлений и read-after-write полного сектора,
пересечение FAT-boundary, вытеснение, I/O/sync failure и cancellation без потери
кеша, сброс admission после отмены. Audit-device проверяет порядок FAT1/FAT2 →
device.sync → directory publication; при ошибке FAT2 новый размер не публикуется,
том poisoned, строки dirty. Sync активного writer не снимает dirty-marker,
закрытие последнего записывает clean-marker последним.

Форматированные FAT12/16:400 кластеров по512B, границы FAT12-entry,
полная проверка после remount. Существующие сценарии FAT32 покрывают5 handles,
параллельные writers/readers, sync, append, abort, rename/delete, dirty mount.
Экспортированные async-fat32.img и multifile-fat32.img проверены fsck.fat -n:
без ошибок и потерянных кластеров. Clippy и optional full release build прошли.

На плате: маленькие файлы и границы512B/32KiB, две загрузки2MiB+15/7,
обрыв PUT50000B после40000B, reconnect/RST, чтение HOME.JPG. Содержимое сверено,
временные файлы удалены, исходный root не изменился.
