# Файловый слой: FAT32, чтение и создание файлов

Собственная реализация в `src/storage`, без Cargo-зависимостей, аллокатора,
RTOS и изменений HAL. Поддержаны чтение и синхронное создание новых файлов.

## Слои и интерфейсы

```text
Приложение → Fat32 / File → Partition → BlockDevice → SdDevice → HAL SDMMC
```

- `BlockDevice`: ёмкость в секторах, максимальный размер передачи,
  `read(lba, &mut [u8])`, `write(lba, &[u8])`. Фиксированный сектор 512 B.
- `Partition`: ограниченная область устройства, преобразует относительный LBA
  в физический и проверяет весь диапазон. Разбор одного из четырёх первичных
  MBR-разделов типа 0x0B/0x0C. GPT/extended partitions пока не поддержаны.
  Через `Partition::new` можно явно задать область, а `Fat32::mount` может
  работать и с устройством, где FAT32 начинается непосредственно с сектора 0.
- `Fat32`: проверка BPB, геометрии, вместимости FAT и корневого кластера,
  выбор активной FAT при отключённом зеркалировании. Тип определяется по
  структуре и числу кластеров, а не строке `FAT32` в загрузочном секторе.
- `read_dir(path, callback)`: потоковый обход каталога, callback возвращает
  false для ранней остановки. Пропускаются удалённые записи, LFN и метки тома.
- `open(path)` → `File`: `len`, `position`, `seek`, `read`, EOF возвращает 0.
  Позиция и подсказка последнего найденного кластера хранятся в File.
  Последовательное чтение не обходит цепочку от начала на каждом вызове.
- `SdDevice` адаптирует наш HAL, владеет Sdmmc и заимствует Timer; HAL не знает
  о разделах и файлах. Статистика показывает число/размер успешных физических
  чтений и время вызовов HAL (включая неудачные).

Пример порядка вызовов (без обработки ошибок):

```rust
let disk = SdDevice::new(card, timer); // card уже инициализирована, configure_bus вызван
let partition = Partition::mbr(disk, 0)?;
let mut fs = Fat32::mount(partition)?;
fs.read_dir("/", |entry| { /* обработать entry */ true })?;
let mut file = fs.open("LOGOS/DUMMY.565")?;
let count = file.read(&mut buffer)?;
file.seek(512)?;
```

Файл эксклюзивно заимствует том на время жизни. Пока нет менеджера таблицы
дескрипторов и нескольких одновременно открытых файлов. Закрытие — окончание
заимствования; Drop не выполняет I/O. File пока предоставляет только чтение.
Запись нового файла целиком выполняется отдельным `Fat32::create_new(path, contents)`;
изменение существующего файла, append и truncate пока не реализованы.

## Память и пакетное чтение

Вместо общего кеша на один сектор используются **два независимых кеша по 512 B**:

1. FAT и записи каталогов — кеш метаданных.
2. Частичные сектора данных файла — кеш краёв.

При выровненной позиции и наличии хотя бы 512 B в буфере данные читаются
непосредственно в буфер вызывающего кода через BlockDevice, пакетами до лимита
устройства (сейчас 8 KiB). Полный файл в память не загружается.

Пакет не пересекает разрыв в цепочке FAT. Если следующий кластер физически
соседний, пакет можно продолжить через границу кластера. Таким образом, при
кластерах 4 KiB реально выполняются передачи 8 KiB. Внутри HAL пока остаётся
SRAM bounce buffer: это не прямой zero-copy DMA в буфер приложения.

Для независимости от кеша метаданных частичные данные не вытесняются при
переходе по FAT. Кеш сбрасывает метку перед чтением: неудачный I/O не публикует
старые данные под новым LBA.

При ошибке чтения позиция файла отражает полностью завершённые куски;
содержимое переданного буфера после ошибки следует отбросить. Проверяются
границы, зарезервированные/плохие кластеры, преждевременный EOC и self-loop.
Обход каталога ограничен общим числом кластеров. Полной проверки целостности
ФС и обнаружения всех перекрёстных/циклических цепочек нет.

## Проверено на плате 2026-11-06

Команда **Z**:

```sh
python3 scripts/display-control.py Z
```

Заново инициализирует карту, согласует режим, монтирует первый MBR-раздел,
выводит до 64 записей корня и до 16 записей в каждом из первых четырёх
подкаталогов. Выбирает наибольший непустой обычный файл среди этих записей
и читает до 1 MiB дважды с буферами 8192 и 777 B, сравнивая FNV-1a по байтам.
Это ограниченная диагностика, не рекурсивный файловый менеджер.

На SDHC 8.01 GB, 4-bit/50 MHz, раздел WEBRADIO:

- Начало раздела LBA2048, 15 644 646 секторов.
- Кластер 8 секторов, 1 951 762 кластера, root=2.
- FAT start=32, data start=30544 (относительно раздела).
- В корне: `STATIO~1.TXT` (300 B), `LOGOS`, `MESHTA~1`.
- Список радиостанций прочитан: FNV-1a `c411c6bd`.
- `LOGOS/DUMMY.565`, **11 552 B**: полностью прочитан пакетами 8192 и 777 B,
  обе контрольные суммы **2621ce57**. Первые байты `31 e9` повторяются.
- Физическое I/O всего диагностического прохода: 35 чтений, 28 160 B,
  **наибольшее чтение 8192 B**, время внутри HAL 13 859 us.
- Общее время прохода, включая каталоги, два чтения, хеш и вывод: 20 056 us.
  Файл маленький, это проверка корректности, не замер предельной скорости ФС.

Данные карты не записывались, форматирование не выполнялось, камера не запускалась.
При работающем LCD framebuffer повторный Z тоже прошёл: хеши совпали,
максимальное чтение 8192 B, framebuffer guards=true, camera=false.
Логи: `target/fat32-first.log`, `target/fat32-files.log`, `target/fat32-display.log`.

20 host-тестов всего; семь новых проверяют FAT32 на sparse-образе блочного
устройства с запрещённой записью: непрерывные и фрагментированные файлы,
пакеты через границы кластеров, невыровненный seek/EOF, подкаталоги, пустой файл,
активную вторую FAT, игнорирование верхних зарезервированных битов FAT entry,
повреждённую геометрию/цепочки, границы раздела и ошибки чтения кеша.

## Следующие этапы

- Длинные имена VFAT/Unicode. Сейчас поиск по ASCII 8.3 без учёта регистра;
  существующие длинные имена доступны через короткий alias (`STATIO~1.TXT`).
  `.` и повторные `/` допустимы, `..` пока отклоняется.
- Таблица открытых файлов/каталогов, если понадобятся несколько одновременно.
- Изменение существующих файлов, потоковая запись/append/truncate, удаление,
  расширение каталогов, интерфейс flush для будущего пишущего File.
- Обработка извлечения/замены карты: закрытие тома и новое монтирование.
  Вставленную другую карту нельзя использовать со старым кешем/контекстом.
- Длительный файловый бенчмарк чтения/записи на большом файле. FAT16, exFAT, ext4 сейчас нет.

## Создание CONFIG.TXT (2026-11-06)

Добавлен `Fat32::create_new(path, contents)`: новый файл ASCII 8.3 в существующем
каталоге, включая пустые файлы и данные на нескольких кластерах. Существующий
файл никогда не затирается (`AlreadyExists`). Растить заполненный каталог
пока нельзя — возвращается `DirectoryFull`. Весь входной срез известен до
начала операции; потокового пишущего File пока нет.

Порядок записи:

1. Проверить имя, каталог, отсутствие одноимённого файла и свободную запись.
2. Проверить clean/no-hard-error flags в активной FAT и всех зеркалах.
   Грязный том отклоняется с `NeedsRecovery`.
3. Очистить clean-shutdown bit в FAT[1]. До завершения операция помечена dirty.
4. Сбросить FSInfo Free_Count/Next_Free в Unknown (`0xffffffff`) в основной и
   резервной FSInfo с корректными сигнатурами; старую подсказку свободного
   кластера можно использовать для поиска, но сам FAT entry обязательно проверяется.
5. Найти свободные кластеры, записать EOC и связи. При зеркалировании менять
   обе FAT, иначе только активную; верхние четыре бита каждого FAT entry
   сохраняются отдельно для каждой копии.
6. Записать данные, обнулить остаток выделенного кластера. Полные сектора идут
   пакетами, ограниченными кластером и лимитом BlockDevice; края дополняются нулями.
7. Сохранить терминатор каталога, затем опубликовать short directory entry
   с первым кластером и размером. Дата 1980-01-01: RTC платы пока недостоверен.
8. Вернуть clean-shutdown bit. В HAL каждая запись дожидается TRANSFER/READY;
   успешный create_new уже синхронно сохраняет данные и метаданные.

Это не журналирование и не атомарная транзакция при потере питания. Ошибка
записи блокирует последующие create на этом объекте. Dirty-flag не снимается
при ошибках, в том числе проверяется грязное зеркало при следующем монтировании/создании.
Может остаться потерянная цепочка кластеров или частично записанный сектор —
для восстановления нужен внешний fsck, автоматического отката/ремонта нет.
`NoSpace` после частичного выделения тоже требует такой проверки.

Консоль **!** вручную создаёт и проверяет тестовый конфиг:

```sh
python3 scripts/display-control.py '!'
```

На SDHC 8 GB создан `/CONFIG.TXT`, 126 B:

```ini
# ESP32-P4 board configuration
[display]
brightness_percent=25
[camera]
enabled=false
[storage]
bus_width=4
clock_hz=50000000
```

После сброса обоих кешей/повторного mount все байты совпали. Затем плата
перезагружена при прошивке окончательного образа: повторная `!` обнаружила
существующий файл, ничего не перезаписывала и снова прочитала совпадающие 126 B.
Z видит CONFIG.TXT в корне, старый `LOGOS/DUMMY.565` по-прежнему даёт
хеш `2621ce57` при чтении с разными размерами буфера.

Конфиг пока демонстрационный: автоматического разбора/применения настроек нет.
Камера не запускалась. Логи: `target/fat32-config-create.log`,
`target/fat32-config-reboot.log`.

Всего 25 host-тестов. Дополнительные пять проверяют создание на нескольких
фрагментированных кластерах, сохранность прежних файлов и верхних битов обеих FAT,
FSInfo/backup, empty/nested file, отказ от перезаписи, активную FAT без
зеркалирования, терминатор на границе секторов, сбой записи данных и dirty mirror.
Форматирование и clippy также проходят.
