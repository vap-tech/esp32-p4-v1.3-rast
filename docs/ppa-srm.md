# PPA SRM: копирование, масштабирование, поворот, отражение

ESP32-P4 rev1.3, bare-metal Rust, 2026-11-15. Реализация в `hal::ppa`, feature
`ppa-lab`. Только RGB565 little-endian; offscreen SRAM/uncached PSRAM, на плате
проверен путь PSRAM→PSRAM. LCD scanout и USB не менялись. Ни C runtime, ни новые
зависимости не добавлены. Reference: локальный ESP-IDF v6.1 `ppa_srm.c`,
`ppa_ll.h`, `dma2d_ll.h`, TRM rev1.3 раздел35.5.3/35.7.2.

## API и геометрия

`unsafe srm_rgb565(input, output, Srm, descriptors, timer)`.
`Srm` задаёт размеры исходной/выходной поверхности, исходный ROI, положение
результата и `Transform`. `Transform` задаёт scale_x/y в шестнадцатых (16=×1,
1=×1/16,32=×2, максимум4095), поворот0/90/180/270° против часовой стрелки и
mirror_x/y. Порядок: scale→rotation→mirrors. Коэффициенты целочисленные,
не округляются скрыто из float. Внутри HAL нет аллокаций и CPU pixel loops.

`Transform::extent()` возвращает фактический размер: floor(width*scale_x/16),
floor(height*scale_y/16), затем перестановка осей при90/270°. Нулевой результат
или размер>8191 отклоняется. `Srm::output_rect()` проверяет помещение результата
в выходную поверхность. В текущем RGB565-контракте ширина поверхности, x ROI и
ширина ROI чётные; высота и y могут быть нечётными. Нечётная выходная ширина
отклоняется, а не дополняется до чётной без ведома вызывающего.

Input/output/descriptors не должны пересекаться; проверяются также DMA-адреса.
Нужны отдельные CPU-owned буферы, workspace≥128B с базой64B-aligned. LCD и другие
DMA не могут владеть этими областями. D-cache OFF, L2=0. Исключительный общий
Claim сериализует JPEG и PPA на уровне всего2D-DMA, включая reset.

## Дескрипторный интерфейс и остановка

SRM сам запрашивает блоки через DSCR-PORT. У TX/RX включён bit11; TX completion
block18×18 для RGB565 с16×16 внутренними блоками rev1.3. RX hb/vb=2 placeholders,
реальные координаты/размеры каждого выходного блока поставляет PPA. Формат
входа/выхода PPA —RGB565; CSC обоих каналов2D-DMA bypass. Burst32B, IRQ disabled.

Перед RX START проверяем, что TX уже выбрал исходный descriptor и очереди AXI
read/backup пусты. JPEG-ожидание TX pixel prefill здесь неприменимо: до SRM START
нет запросов пикселей, descriptor FSM ждёт PPA. Ожидание ограничено100мс,
фиксированных задержек нет. Используется DIG-734 workaround из IDF: отключение
конкатенации блоков, когда последний transfer unit не заполняет RX FIFO.
Проверены, в частности, размеры66×17 и80×33, активирующие этот обход.

Любые PPA parameter errors, DMA errors, RID/RRESP/WRESP fatal. Операция polling,
таймаут1с, внутри ожидания обслуживается HP-worker. На всех обычных ошибочных
путях producer останавливается, оба DMA подтверждают reset-safe, только затем
буферы можно освободить. После EOF ждём write drain. Невозможность подтвердить
безопасную остановку вызывает panic с удержанием памяти, не небезопасный возврат.
Это ещё не фоновая очередь для HTTP/RTC/audio; длительные операции блокируют HP0.

## CPU-эталон и качество

Все пиксели, включая область вне ROI, сравниваются с независимо рассчитанным
CPU-эталоном. Источник сверяется на неизменность, output/descriptors окружены
canaries. При scale=1 совпадение точное. Проверены все16 сочетаний4 поворотов
и4 зеркальных режимов на несимметричном цветном узоре со смещениями ROI.

Документация IDF указывает bilinear interpolation. На плате подтверждено
совмещение центров пикселей:
`source=(destination+0.5)/scale-0.5`, с прижатием к границам ROI. Это важно на
резких переходах: первоначальный origin-based CPU reference не совпадал.
При масштабировании эталон считает bilinear в5/6-bit компонентах, PPA — через
ARGB8888; допускаем максимум1 шаг каждого native RGB565 канала. На проверенных
данных максимум `[1,1,1]` для дробного масштаба, остальные случаи часто точные.
Это характеристика нашего тестового корпуса, не универсальная гарантия ошибки
для любого изображения. Сами размеры и запись вне ROI проверяются точно.

Проверены ×2,×1/2,×1/4,×1/16,19/16 поX и13/16 поY, неодинаковые масштабы поосям,
а также scale+rotate+mirror. Всего24 небольшие операции в одной серии.

## Измерения

Время включает настройку/работу/остановку аппаратуры; исключает выделение,
заполнение исходника/канареек и CPU-проверку. LCD одновременно читает прежний
framebuffer. Текущие консервативные параметры, без настройки приоритетов/burst.

| Операция | Время одного замера |
|---|---:|
| ROI20×12, scale1, повороты/отражения | ~66–81мкс |
| Copy1024×600 (source stride1024, rows608) |63275мкс |
| Rotate90°1024×600→600×1024 |64696мкс |
| Scale1024×600→512×300 |56928мкс |
| Scale320×240→640×480 |11812мкс |

Все большие выходы проверены попиксельно, canaries целы, AXI errors=0.
Это не сравнение с CPU memcpy: SRM читает блоки с halo, преобразует формат
внутри PPA и снова пишет. Предпочтительный будущий путь простого копирования
может быть M2M2D-DMA, а не SRM. Калибровку burst/приоритетов оставили отдельно.

## Команды

```
./scripts/image.sh --features ethernet-pie,jpeg-lab,ppa-lab
```

После остановки web через ESC:

```
:display ppa test
:display ppa srm
:display ppa srm-large
:display ppa srm-stress
```

`test` — прежний FILL; `srm` —24 небольших преобразования; `srm-large` —6 граничных/
больших случаев; `srm-stress` —10 повторов маленькой серии. Ничего на SD не пишет
и выход на LCD не публикует. Alpha blend, другие форматы и framebuffer swap —
отдельные следующие этапы.

Финальная проверка:240 малых преобразований (10×24), все source/guards/pixels
прошли, AXI error counters нулевые. Затем FILL→JPEG test (включая timeout раннего
EOI и восстановление)→6 больших SRM→HOME.JPG; все операции успешны, checksum
JPEG прежний. Стек high-water53348/65536B, guard цел.121 host test,
target Clippy combined/normal/ppa-only, fmt и diff-check прошли. Проверенные
бинарники/логи в игнорируемом `target/jpeg-lab/`. После тестов на плату возвращена
стабильная Ethernet-PIE сборка; исходники SRM пока без отдельного коммита.
