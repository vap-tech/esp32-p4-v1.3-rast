# Текстовый редактор

Редактор находится целиком в браузере, HTML/CSS/JS без зависимостей. Пункт
«Редактировать» в меню файла открывает native dialog с textarea. Обычный клик
по файлу пока сохраняет прежнее поведение; расширения для открытия в редакторе
ещё не настраиваются. Демо поддерживает чтение/сохранение текста в памяти.

## Ограничения и текст

Максимум1048576байт UTF-8, включая BOM и сохранённые переводы строк. Метаданные
и Content-Length проверяются до чтения; потоковое чтение ограничено тем же
пределом и отменяется при превышении. При недоступном stream API лимит также
проверяется после arrayBuffer. Декодирование UTF-8 строгое, NUL отвергается как
двоичные данные. Другие кодировки автоматически не угадываются.

Неизменённый текст сохраняется исходными байтами, включая BOM и смешанные
переводы строк. После правок сохраняются BOM и первый найденный стиль переводов
строк (CRLF/CR/LF); смешанные строки нормализуются в этот стиль. Окончание файла
новой строкой не добавляется автоматически. Предел проверяется по кодированным
байтам, а не числу символов в textarea.

## Сохранение существующими запросами

Папка и имя берутся из открытого файла, а не текущей папки менеджера.

1. PUT `/fs/папка/.EDIT-<random>.TMP` с новым содержимым.
2. Только после201: DELETE оригинала (404 при повторной попытке допустим).
3. POST rename временного файла в исходное имя.

Это несколько клиентских запросов, без нового серверного метода/Replace и без
HEAD-проверки перед записью. Резервная копия и откат не создаются.
При «Сохранить как» имя задаётся prompt в той же папке. Для другого имени
оригинал не удаляется: PUT временной копии → rename под новым именем.
Занятое имя →409, без удаления существующего файла. После успеха редактор
работает уже с новым путём.

При отказе rename после DELETE оригинал может отсутствовать; временная копия
остаётся на SD. Повторное сохранение допускает404 на DELETE и может восстановить
файл. При ошибке до удаления оригинала временная копия убирается best-effort.
При потере питания/закрытии вкладки нет гарантий сохранности, предупреждений о
несохранённых правках нет. Диалог закрывается без подтверждения; dirty-индикатор/
автосохранение/локальное восстановление не добавлены. Фактический отказ запроса
отображается в редакторе. Проверки одновременных правок/CRC/ETag не реализованы.

Ctrl/Cmd+S сохраняет, Ctrl/Cmd+Shift+S открывает «Сохранить как». Во время
сохранения поле и кнопки сохранения заблокированы; основной close/Escape доступен.
Обычная файловая очередь сериализуется флагом mutating; при этом сервер продолжает
обслуживать остальные подсистемы. beforeunload редактор не добавляет. Общий
предыдущий обработчик предупреждает только о выполняемой очереди загрузок.

## Проверки

Node: граница1МиБ, превышение UTF-8 байтами, отмена потока, запрет бинарного
ввода, BOM/CRLF, неизменённые байты, ожидание PUT перед rename, Save As конфликт,
захваченная папка, допустимая потеря после DELETE и повторное сохранение после отказа rename, закрытие без записи.
Chromium: desktop/mobile320/360, открытие/сохранение/Save As, отсутствие overflow
и JS exceptions. На плате в отдельной тестовой папке проверены реальное меню,
правка BOM+CRLF, Save As,409, закрытие без сохранения, чтение/запись ровно1МиБ и
блокировка сохранения сверх лимита. Тестовая папка удалена. Плата и её Rust API
не менялись, выложена только SD-страница.
Артефакты: `target/editor-browser.log`, `target/editor-live.json`,
`target/ux-redesign/editor-*.png`, `target/ux-live/editor-live*.png`.
