# Профиль записи SD — 2026-11-13

ESP32-P4, CPU 160 МГц, I-cache ON, D-cache OFF, L2=0, PSRAM uncached.
LCD активен. Файлы по 8 МиБ, FAT32 на установленной карте 250 ГБ.
Это измерения данного носителя и прошивки, не предел SD-интерфейса.

| Путь записи | Время | МиБ/с |
| --- | ---: | ---: |
| SRAM → FAT → SD без HTTP | 4,317 с | 1,853 |
| HTTP → FAT → SD до исправления | 12,384 с | 0,646 |
| HTTP → FAT → SD после исправления | 6,948 с | 1,151 |

HTTP чтение после исправления: 3,685 МиБ/с. Файлы прочитаны обратно и
сверены полностью; временные файлы удалены, исходный список каталога сохранён.

## Причина и исправление

HTTP-заголовок сдвигал начало тела относительно 512-байтного сектора.
Промежуточные записи не были выровнены по сектору, поэтому FAT выполняла
read-modify-write краёв. Число запросов в области данных: 5636 до исправления,
1621 после; SRAM-тест — 1024. Число CMD13 сократилось с 15797 до 8105.
Дополнительные чтения секторов данных исчезли.

Теперь обработчик собирает уже доступные TCP-фрагменты в общий scratch,
промежуточную порцию округляет вниз до 512 байт, а последний хвост пишет
точной длины. Дополнительного буфера нет. Остаточная разница с SRAM-тестом
связана в том числе с TCP RX 6 КиБ и границами кластеров: это не одинаковое
разбиение запросов. Закрытие входа до полного тела прерывает загрузку.

## Оставшиеся затраты

В SRAM-тесте суммарное ожидание готовности карты — 2,346 с, запросы в
области метаданных — 2,035 с. После HTTP-исправления: 4,041 с и 2,014 с.
Эти интервалы вложены друг в друга; складывать их нельзя. Ready включает
CMD13, период опроса и задержку обслуживания, а не только физическую запись
карты. Следующий кандидат — уменьшение метаданных и анализ ready polling.
Кеширование FAT потребует отдельного решения о dirty/sync и сбоях питания.

## Конкурентная запись

Два HTTP PUT по 8 МиБ одновременно с дописыванием короткой строки лога
примерно каждые 100 мс: загрузки 22,90 и 22,93 с; 128 строк.
Клиентская задержка строки: медиана 78,24 мс, p95 91,01 мс, максимум 101,83 мс.
Оба файла и последовательность строк сверены полностью. Это задержка HTTP
целиком, не гарантия времени обслуживания датчика/ISR и не чистое время SD.
Отдельно прошли reconnect, три параллельных RAM-клиента, разрыв загрузки
клиентом, неполное тело запроса и последующее чтение/запись SD.

## Воспроизведение диагностики

Собрать `./scripts/image.sh --features diagnostics`, прошить firmware.bin.
Команда `sd benchmark files 8` (helper `--sd-files-bench 8`) создаёт новый
уникальный файл, пишет из SRAM, проверяет чтением и удаляет его. Ethernet
инициализируется до теста, но внутри измеряемого цикла HTTP и network poll
не выполняются. Время чтения включает побайтовую проверку CPU.

Только diagnostics предоставляет POST `/fs/path` с Content-Length до 512 Б
для дописывания существующего лога. Это тестовый маршрут, без exactly-once
и отката уже записанного append при разрыве соединения. В обычной сборке
этот метод возвращает 405. PUT продолжает создавать новый файл.

`SD PROFILE` печатает 24 накопительных счётчика:
reads, writes, read_bytes, write_bytes, setup_us, data_us, stop_us, ready_us,
read_request_us, write_request_us, metadata_calls, metadata_bytes, metadata_us,
payload_calls, payload_bytes, payload_us, CMD13, errors, read512, write512,
write1024, write2048, write4096, writeOther.

Setup включает подготовку DMA; data — до наблюдаемого завершения; stop —
остановку DMA и возврат буфера. Времена включают задержки кооперативного
обслуживания. Классификатор FAT32 считает метаданными reserved/FAT и первый
кластер корня, только если он единственный (проверяется EOC). Для вложенных
каталогов и многокластерного корня классификация неполна. `shared=true`
означает, что разность глобальных счётчиков включает другие передачи.
`rx_empty_us` учитывает также ожидание достаточной порции для выравнивания.
Счётчики 32-битные; длинные прогоны могут переполнить микросекунды.

Профилировщик и тестовые команды исключены из default. В default остаётся
исправление разбиения HTTP-записи. Логи эксперимента находятся в
`target/storage-profile/` (локальные артефакты, не исходники).

После серии из 312 HTTP-запросов сервер завершился штатно: rx_errors=0,
стек 54672/65536 Б, guard_ok=true. Host-тесты: 83 в core и 83 с diagnostics;
Clippy core/diagnostics прошёл. Полная сборка diagnostics+wifi+software-jpeg
также помещается в карту памяти. На плату возвращена default-сборка.
