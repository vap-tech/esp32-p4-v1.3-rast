# Микрофон → WAV на SD

Запуск только явной командой, никакой автоматической записи при загрузке:

```sh
python3 scripts/display-control.py --record REC0004.WAV --record-seconds 30
python3 scripts/display-control.py --play REC0004.WAV
```

В консоли: `:audio record REC0004.WAV 30`. Длительность 1…600 секунд.
Файл создаётся новым, существующие файлы не перезаписываются. ASCII 8.3,
каталоги должны уже существовать. STOP на экране (тот же прямоугольник,
что у будильника), ESC или Ctrl+C в скрипте завершают запись и закрывают WAV.
Старт запрещён при активной камере/будильнике; D-cache OFF, L2 bypass.

На экране во время записи: REC + количество целых записанных секунд,
логарифмический индикатор пика примерно -72…0 dBFS и STOP. Часы обновляются.
Динамик выключен (PA11=0, DAC muted); обратной акустической связи нет.
После завершения временные элементы стираются, часы продолжают работу.

## Тракт и память

ES8311 ADC → GPIO48 / I²S1 RX → AHB DMA RX0 → кольцо SRAM → FAT32 writer.
TX передаёт тишину, обеспечивая MCLK/BCLK/WS. Выходной PCM16 mono 16000 Гц,
32000 байт/с. Левая половина RX-слова — микрофон, правая — DAC reference,
для диагностики отдельно считается её максимум. Пропускается первое неполное
RX-слово, затем сохраняется заданное число кадров (либо до STOP).

Настройки аналогового микрофона соответствуют старой прошивке и
[драйверу Espressif ES8311](https://github.com/espressif/esp-adf/blob/master/components/esp_codec_dev/device/es8311/es8311.c):
SDOUT unmute 0A=0C, analog mic 14=1A, PGA 16=04 (24 дБ), 44=58 (ADCL+DACR).
Зависимости SDK не добавляются; источник использован только как описание регистров.
Качество/уровень аналогового сигнала ещё требуют проверки голосом пользователя.

RX-ring: 8×512 stereo words, 16 КиБ PCM + 512 байт дескрипторов, 64-byte
выравнивание и guards. Резервируется 17024 байта work-арены; DMA пользуется
некешируемым SRAM alias. CPU копирует mono PCM в 1024-byte scratch и возвращает
блок DMA до синхронной записи SD. Запас кольца около 256 мс. RX имеет приоритет,
тач опрашивается в свободные интервалы примерно раз в 20 мс, UI — раз в секунду.
Переполнение/descriptor error и отсутствие кадров >200 мс возвращают ошибку.
Все пути после запуска RX паркуют RX/TX до возврата выделенной памяти;
неподтверждённая остановка DMA приводит к panic, а не повторному использованию.

## Файл и ошибки

WAV имеет RIFF/fmt/JUNK/data: заголовок занимает 512 байт, PCM начинается
со второго сектора. Так нет постоянного частичного SD-сектора между блоками.
При завершении `FileWriter::rewrite_prefix` обновляет заголовок фактической
длиной, затем finish дописывает tail/slack и публикует файл в каталоге.
После закрытия запись открывается заново, разбирается WAV-заголовок и весь PCM
повторно читается с SD со сверкой FNV-1a32, посчитанного по входящим сэмплам.

Здоровый поток при ошибке RX/кодека отменяется через abort. Ошибка записи SD
или переписывания заголовка отравляет writer и оставляет том dirty по общему
контракту FAT32; fsck/восстановление ещё не реализованы. Обрыв питания до
finish также не гарантирует сохранение файла/освобождение цепочки.
Подтверждённый STOP завершает файл, в отличие от обрыва питания.
Срабатывание будильника во время записи будет обработано после возврата
в основной цикл, одновременные запись и мелодия пока не предусмотрены.

## Проверки 2026-11-12

- REC0001.WAV: 160000 кадров / 10 с, PCM 320000 байт, FNV=224d1334,
  повторное чтение совпало; peak=269, mean_abs=8, right reference=0.
- REC0002.WAV: 960000 кадров / 60 с, PCM 1920000 байт, FNV=fa8e2586,
  чтение совпало; peak=432, mean_abs=10. Максимальная запись SD 35.020 мс,
  RTC+UI 25.611 мс. Оба опыта закончились по таймеру, физический STOP
  пользователем в этих записях пока не подтверждён.
- REC0003.WAV: досрочный Ctrl+C → ESC, 64511 кадров / 4.032 с PCM,
  elapsed 4.037 с; header и PCM прочитаны со сверкой FNV=ff959985.
- Во всех записях RX/TX остановлены, guard=true; стек 7208/16384, guard цел.
- Сигнал очень тихий. Реакция на голос, разборчивость и качество микрофона
  не подтверждены; ненулевые сэмплы сами по себе этого не доказывают.
- 72 host-теста проходят, 2 ignored; clippy all-features, сборка, fmt проходят.
  Тесты покрывают patch prefix до/после первого сектора, сохранение хвоста,
  отказ I/O без публикации, WAV с JUNK/alignment и шкалу индикатора.

Логи: target/recorder/ (ignored). Ethernet link=false, файл на ноутбук ещё
не выгружался. Это короткие записи, долговременный stress-test не проводился.

REC0003.WAV затем воспроизведён штатным проигрывателем: 64511 кадров,
MEDIA PLAY DONE Ok, часы обновились 3 раза, DAC/PA остановлены штатно.
Это проверка совместимости записанного WAV с проигрывателем, не подтверждение
разборчивости на слух. Финальный статус LCD: underrun=0, guards=true;
стек после записи и воспроизведения 9648/16384, guard_ok=true.

### Голос, STOP и экран: последующие проверки

REC0004: 10 с, peak=3755/32768, mean_abs=231, FNV=7cd37acb;
пользователь подтвердил разборчивое воспроизведение голоса.
Физическая кнопка STOP подтверждена в REC0007: stopped=true, 393727 кадров,
снятие RX/TX и закрытие WAV без ошибок. Будильник/AF при записи не меняются.
Вспышки экрана воспроизведены как LCD underrun при рисовании UI. В recorder
добавлены lcd_write/lcd_ui и стадийные LCD counters; запись SD в опытах не
вызвала событий. Исправление write_run (u32 + небольшие окна для LCD) и
границы подтверждения описаны в framebuffer.md. Последняя прошивка имеет
логарифмический meter, 73 host-теста проходят, 2 ignored.
