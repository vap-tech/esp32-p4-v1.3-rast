# Страница на SD

Главная страница `GET /` и `/index.html` сначала открывает `/www/index.html`
на FAT32. Файл — обычный несжатый UTF-8 HTML, текущий размер 38607 байт.
Он читается через FileTable порциями общего HTTP scratch, целиком в SRAM
не загружается. HEAD возвращает длину без тела. Страница имеет обычный
`Cache-Control: no-store`, поэтому изменения видны после перезагрузки браузера.

Если файла нет или вместо него каталог, сервер отдаёт прежнюю gzip-страницу
из Flash. Ошибки доступа/занятый файл/неисправность ФС возвращаются как ошибки,
а не маскируются запасной страницей. После отправки HTTP-заголовков переключить
источник уже нельзя. Встроенная страница сохраняется в прошивке; её CRC пока
проверяется при запуске web-run, как и раньше. Работа web-run без смонтированной
SD этим изменением не добавлена.

Установка без перепрошивки:

```sh
python3 scripts/install-web.py --url http://192.168.1.167
```

Скрипт создаёт `/www`, загружает `frontend/index.html`, проверяет чтение с SD и
главный URL. При совпадающем файле повторный запуск ничего не пишет; отличающийся
файл не перезаписывает, чтобы не потерять будущие пользовательские правки.
Для обновления существующий файл следует сначала сохранить или переименовать
через файловый интерфейс. PUT пока создаёт новый файл, а не заменяет существующий.

Каталог виден в файловом менеджере, отдельные ресурсы можно получать через
`/fs/www/имя`. Сейчас страница самодостаточна, CSS/JS внутри HTML. Это основа
для будущего редактора, сам редактор и атомарное сохранение правок ещё не добавлены.

На плате проверены: точное совпадение HTML, HEAD, временное переименование
index.html → gzip fallback из Flash → возврат файла и страницы с SD.

Для принудительной загрузки встроенной страницы: **`/flash`** или `/?flash=1`
(также `/index.html?flash=1`). Они обходят открытие `/www/index.html` целиком,
поэтому работают и при существующем, но испорченном HTML. GET и HEAD отдают gzip
из Flash. `/flash?path=...` сохраняет режим при навигации по папкам и reload: UI
запоминает каталог в URL. Для восстановления страницы удобнее использовать `/flash`.
Это не режим восстановления несмонтированной/повреждённой ФС: запуск web-run
по-прежнему требует успешного mount SD.

На плате проверено с временным испорченным index.html: обычный `/` отдавал
тестовое тело, принудительный Flash-адрес — исходную страницу, включая HEAD.
После проверки исходный index.html восстановлен, содержимое каталога прежнее.
