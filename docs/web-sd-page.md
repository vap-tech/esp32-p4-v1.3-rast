# Веб только на SD

Начиная с2026-11-17 встроенная страница удалена. `/` и `/index.html` читают
`/www/index.html` порциями общего HTTP scratch; целиком в SRAM HTML не хранится.
HEAD возвращает длину без тела. При отсутствии файла —404; `/flash` и
`?flash=1` больше не поддерживаются. Запуск веб-сервера не зависит от Flash asset.
Смонтированная рабочая SD по-прежнему нужна для файлового сервиса.

## Установка и восстановление

Обычное обновление с сохранением прежней страницы:

```sh
python3 scripts/install-web.py --url http://192.168.1.167 --replace
```

Если страница сломана или удалена, браузер не нужен:

```sh
# Если /www отсутствует: создать;409 означает, что имя уже существует.
curl -X MKCOL http://192.168.1.167/fs/www
# PUT создаёт новый файл. Если имя уже занято, сначала удалить старый:
curl --fail -X DELETE http://192.168.1.167/fs/www/index.html
curl --fail -T frontend/index.html http://192.168.1.167/fs/www/index.html
# Отдельный ресурс при необходимости обновляется так же:
curl --fail -X DELETE http://192.168.1.167/fs/www/photo-tools.js
curl --fail -T frontend/photo-tools.js http://192.168.1.167/fs/www/photo-tools.js
```

Запрос DELETE к отсутствующему файлу вернёт404: можно сразу выполнять PUT.
PUT в `/fs/...` всегда CreateNew, в том числе в `/www`: совпадение имени →409,
старое содержимое не меняется. Специального режима Replace/truncate, POST для
загрузки веба и исключений для index.html/JS нет. `/www/...` — адрес чтения,
изменение файлов выполняется через обычный файловый API `/fs/www/...`.
DELETE→PUT не атомарен: при обрыве страницу нужно загрузить повторно.
Для штатных обновлений install-web.py остаётся temp+readback+backup+rename.

## Сборка и память

`image.sh` вызывает pack-image.py только с RAM image и выходным именем.
FlashPage/Asset API, стартовая проверка CRC веба и gzip-генерация удалены.
`frontend/index.html.gz` больше не нужен и удалён. Бывший Flash-слот
0x100000..0x10ffff на подключённой плате отдельно стёрт, после чего залита
прошивка без страницы. Остальная Flash и SD не стирались.

Промежуточный вариант с прямой перезаписью удалён по решению пользователя.
Окончательный замер и проверка DELETE→PUT приведены ниже.

## Окончательный замер: без особой перезаписи

| Показатель | Исходный со Flash-вебом | Окончательный | Разница |
|---|---:|---:|---:|
| firmware.bin |1060568Б|606676Б|−453892Б|
| SRAM runtime payload |353236Б|352660Б|−576Б|
| Начальная рабочая SRAM-арена |75648Б|76224Б|+576Б|

Относительно промежуточного варианта с Replace/truncate удаление перезаписи
уменьшило payload/образ на1584Б и вернуло1600Б рабочей SRAM с учётом выравнивания.
HTML уже раньше не копировался целиком в SRAM: большая экономия образа —
удалённый gzip20165Б и FF gap до0x100000. Эти FF-байты не были оперативкой.

134host tests (включая журнал с1000архивными файлами), frontend/photo-tools,
5packer tests прошли. На плате: существующий index отклоняет повторныйPUT409
и сохраняет байты; DELETE204 → отсутствие страницы404 → PUT201 восстанавливает
исходный SHA256. POST загрузки и PUT по статическому `/www/...` дают405;
изменения — только обычным файловым API `/fs/...`. Встроенный веб не возвращён.
Артефакты: `target/delete-put-*`, `target/test-delete-put-recovery.py`.
