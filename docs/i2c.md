# I²C1: собственный master для ESP32-P4 rev 1.3

Код: [src/hal/i2c.rs](../src/hal/i2c.rs). Без SDK, RTOS, DMA, IRQ и внешних Rust-зависимостей. Проверено на нашей Guition 2026-11-04, прямой запуск через ROM.

## Подключение и API

**SDA GPIO7, SCL GPIO8, I2C1, 7-битные адреса, номинально 100 кГц.** Пины настроены open-drain с включённым входом и внутренними pull-up; номиналы внешних подтяжек платы неизвестны. IO_MUX function 1, GPIO matrix: SDA signal 71, SCL signal 70, маршруты настроены в обе стороны.

```rust
let mut bus = unsafe { hal::i2c::I2c::new(&mut timer) };
bus.probe(0x5d, &mut timer)?;
let mut id = [0; 4];
bus.write_read(0x5d, &[0x81, 0x40], &mut id, &mut timer)?;
// id == [0x39, 0x31, 0x31, 0x00]
```

Пример предназначен для функции с результатом `Result<_, hal::i2c::Error>`. Конструктор `unsafe` требует единственного владения I2C1, GPIO7/8 и соответствующими clock/matrix registers. Объект не `Send`/`Sync`, транзакции требуют `&mut self` и `&mut Timer`. HAL доступен из библиотечной части пакета: `use esp32_p4::hal;`.

- `probe(address, timer)` — START, address+W, проверка ACK, STOP. Не отправляет номер регистра или данные.
- `write_read(address, tx, rx, timer)` — до **30 байт TX** и **32 байт RX**. При двух непустых фазах используется repeated START. Все переданные адреса и TX-байты проверяются на ACK; последний принятый байт завершается NACK, затем STOP.
- Пустой `rx` — write-only; пустой `tx` при непустом `rx` — read-only. Обе фазы пусты — probe.
- Допустимы адреса `0x08…0x77`; зарезервированные адреса исключены. Превышение длины и неверный адрес отклоняются до обращения к аппаратуре.
- В prefix `tx` вызывающий сам кодирует адрес регистра: у ES8311 один байт, у GT911 и камеры — два, старший первым. В HAL нет скрытого сдвига 7-битного адреса API или предположения об адресации регистров устройства.

## Аппаратная реализация

Используется FIFO mode и массив команд контроллера, максимум 7 из 8 команд на одну комбинированную операцию. Кодировки для этой модели: RESTART=6, WRITE=1, READ=3, STOP=2, END=4. TX заранее помещается в 32-байтный FIFO, включая адреса фаз. RX FIFO опустошается **во время выполнения передачи** в polling loop. Ожидание окончания перед чтением полного FIFO приводило к остановке на границе 32 байт; текущая схема проверена на полном RX.

| Узел | Регистры / настройка |
|---|---|
| I2C1 | Base `0x500C5000` |
| Контроль | CTR `+0x04`, master bit 4, START bit 5, FSM reset bit 10, configuration update bit 11 |
| Статус | SR `+0x08`, bus busy bit 4, RX count bits 8..13 |
| FIFO | CONF `+0x18`, DATA `+0x1C`; пороги RX=31, TX=4 |
| Ошибки/завершение | INT_RAW `+0x20`, INT_CLR `+0x24`; CPU interrupt enable `+0x28` выключен |
| Команды | `+0x58…+0x74`, ACK check bit 8, read NACK bit 10, opcode bits 11..13 |
| APB clock | `0x500E601C`, bit 13 |
| Functional clock/source | `0x500E6040`, enable bit 27, source bit 26=0 (XTAL) |
| Divider | `0x500E6044`, integer divider 1, fractional part 0 |
| Reset | `0x500E60C4`, bit 21 |

Источник — кварц 40 МГц. Low period: 200 ticks; high+wait-high: 102+98 ticks. Настройки следуют расчёту из локального LL: SDA hold 50 ticks, sample 100 ticks, START/STOP setup/hold по 200 ticks. Glitch filters — 7 ticks на SDA/SCL. **100 кГц — расчётная настройка, отдельное измерение SCL осциллографом не проводилось.**

## Ошибки и ограничение ожидания

| Ошибка | Причина |
|---|---|
| `InvalidRequest` | Недопустимый адрес или длина буферов |
| `BusBusy` | Контроллер не освободился за 2 мс перед началом |
| `Nack` | Устройство не подтвердило адрес либо TX-байт |
| `Timeout` | Аппаратный SCL timeout или программный предел 20 мс на передачу |
| `Arbitration` | Аппаратный arbitration-lost flag; multi-master не поддерживается |
| `Fifo` | RX/TX overflow, лишние данные либо неверное итоговое число байт |

Аппаратный timeout: `2^17` тактов / 40 МГц ≈3,277 мс удержания SCL. Программные дедлайны используют SYSTIMER и разность по модулю `2^48`; они предполагают исправный и включённый таймер. После ошибки FSM и FIFO переинициализируются с прежними timing settings. При `Err` RX-буфер может содержать частично принятые данные; использовать его как успешный ответ нельзя.

Это не полное восстановление физически зависшей шины: генерации девяти импульсов SCL и отдельной GPIO-процедуры bus-clear пока нет. Clock stretching, принудительно зажатые линии, multi-master, длинные передачи с пополнением TX и частоты 400 кГц/выше не проверялись.

## Что подтверждено на нашей плате

Три последовательных цикла дали одинаковый набор ACK: **`0x14`, `0x18`, `0x32`, `0x36`, `0x5D`**.

| Адрес | Чтение | Результат |
|---|---|---|
| `0x18` | Отдельно `0xFD`, `0xFE`, `0xFF` | `83 11 01`: ES8311, версия 1 |
| `0x5D` | GT911 `0x8140`, 4 байта | `39 31 31 00` / `911\0` |
| `0x14` | Та же операция | Тот же Product ID. Совпадает с прежним наблюдением альтернативного ответа touch; не считать автоматически второй микросхемой. |
| `0x36` | Camera ID `0x300A`, 2 байта | `56 02` / `0x5602`, соответствует OV02C10 из старой описи |
| `0x32` | Чтение с prefix `0x00`, 7 байт | Например `35 55 00 7F 01 01 F4`; первый байт меняется со временем. Это сырые данные устройства, которое старая опись называет RX8025T; корректность календаря и точная модель данным чтением не подтверждены. |

**Особенность ES8311:** блочное чтение трёх байт с `0xFD` давало `83 FF FF`. Для идентификации нужны отдельные register reads; три обращения дают `83 11 01`. Не предполагать автоинкремент адреса этого кодека.

Дополнительные аппаратные проверки:

- RX 32 байта от `GT911 0x8140`: передача успешна, первые 4 байта `911\0`.
- GT911: запись только двухбайтного register pointer, STOP, затем отдельное read-only чтение: Product ID совпал.
- Отсутствующий `0x08`: `Nack` за **111–112 мкс**, следующие обращения к периферии работают.
- `0x80`: `InvalidRequest`, физической передачи нет.
- Во время доводки проверен возврат `Timeout` на граничном чтении FIFO и последующие успешные обращения; после исправления RX polling граничная проверка проходит.
- Все три итоговых цикла завершились, неожиданных ошибок и сообщений reset нет. `cargo fmt --check`, `cargo clippy --release -- -D warnings` проходят.

Прошивка повторяет диагностику каждые 5 секунд и держит GPIO23 low (подсветка выключена). Сохраняемые настройки устройств не записываются: TX-фазы диагностики задают только register pointer либо состоят лишь из адреса. В RX32 область чтения включает status/point registers touch; обработка и подтверждение событий touch пока не реализованы.

Логи: `target/i2c-rx-drain.log`, сводка `target/i2c-check.json`. `target/` исключён из Git. Образ проверки — **8048 байт**.

## Карта памяти после добавления I²C

Код и константы остаются в HP TCM `0x30100000…0x30101FFF`. Для освобождения TCM стек и BSS перенесены в нижние 16 КиБ SRAM `0x4FF00000…0x4FF03FFF`, initial SP=`0x4FF04000`. До установки SP стартовый asm принудительно включает L2 RAM clock: `HP_SYSTEM_L2_MEM_RAM_PWR_CTRL0` по `0x500E5060`, bit 0. Это clock force-on, не включение кеша или MMU.

Linker требует оставить минимум 8 КиБ под стек после BSS. Инициализированные `.data` по-прежнему загружаются ROM в TCM. На итоговом ELF код+константы занимают 7976 байт TCM; стек находится отдельно. Кеши, PSRAM и второе ядро не используются.
