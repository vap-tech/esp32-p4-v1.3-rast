# JD9165: первый запуск собственного DSI

Плата JC1060P470C, ESP32-P4 rev 1.3. Собственный Rust без Cargo-зависимостей,
ESP-IDF/runtime/RTOS. `hal::dsi` настраивает DSI, `devices::jd9165` выполняет
сброс и 50 команд панели из сохранённого voice-проекта. Это этап проверки
аппаратного генератора полос; framebuffer, PSRAM и DMA пока не реализованы.

## Питание, линии и тактирование

- GPIO27 — LCD RESET, active low: high 10 ms → low 10 ms → high 120 ms.
  GPIO27 также может принадлежать USB FS OTG. Здесь FS OTG не используется;
  USB Serial/JTAG на GPIO24/25 продолжает работать.
- GPIO23 — подсветка, активный высокий уровень. Текущий драйвер использует
  LEDC PWM 20 кГц / 10 бит; после успешной инициализации устанавливает
  5% без перебора уровней. При ошибке старта duty остаётся 0.
  Начальная проверка DSI ниже выполнялась с постоянным high.
- DSI bus 0, VC0, две фиксированные аппаратные data lanes, 550 Mbps/lane.
- PHY питается от **LDO3 = 2500 mV**. LDO channel 3 = unit 2, но PMU
  `ext_ldo[1]`, адреса `0x501151C0/C4`. Подбор DREF/MUL учитывает доступные
  калибровки eFuse VO3 (только чтение); включаются software ownership и
  ripple suppression, bypass 3.3 V выключен.
- **Rev 1.x:** config clock и PLL reference используют общий PLL_F20M.
  Нельзя переносить mux отдельного XTAL reference с rev 3.x.
  Исходный SPLL 480 MHz оставлен настроенным ROM, REF_20M divider=24.
  D-PHY PLL M=110, N=4 → 550 Mbps; HS range=0x17.
- Escape divider=4 → 17.1875 MHz; timeout divider=7 → ~9.82 MHz.
- DPI clock gate настроен на PLL_F240M / 5 = **48 MHz**. В старом SDK
  запрашивалось 50 MHz, но целый делитель округляется до 5. Генератор VPG
  использует host video timings; внешние bridge DPI pixels выключены.

## Регистры и протокол

Host `0x500A0000`, bridge `0x500A0800`, HP clock/reset `0x500E6000`.
Все определения взяты из **hw_ver1** локального ESP-IDF v6.1.

DCS передаётся в LP: short write без параметра DT=0x05, с одним DT=0x15,
long write DT=0x39. VC0, команда/параметры по 8 бит. У long write размер
включает байт команды; payload пакуется little-endian по 32 бита. Поддержано
до 63 параметров, с ожиданием свободного FIFO и опустошения TX после пакета.
Чтение DCS: maximum return packet DT=0x37, read DT=0x06, BTA, 1…4 байта.
PHY lock, stop state, FIFO и чтение ограничены таймером по 100 ms.

Порядок: LDO → clocks/reset → PHY PLL → command mode → LCD reset → DCS ID
`0x04` → MADCTL `0x36=00` → 50 vendor commands → DISPON `0x29` → power mode
`0x0A` → VPG/video → подсветка. Таблица заканчивается sleep out `0x11,00`
с паузой 120 ms и display on `0x29,00` с паузой 50 ms; сохранена без изменений.
Как в исходном приложении, затем отдельно посылается DISPON без параметров.
Не добавляется общий COLMOD `0x3A`, которого нет в исходном драйвере JD9165.

Тайминги панели: 1024×600, RGB565, HSW/HBP/HFP=20/136/160,
VSW/VBP/VFP=2/12/20. Host использует byte clock 68.75 MHz и ожидаемые
50 MHz: HSA=28, HBP=187, HLINE=1843, VSA=2, VBP=12, VFP=20, VACTIVE=600.
Расчётная частота VPG по HLINE и 634 строкам ≈58.84 Hz; физически не измерялась.
Burst with sync pulses, LP в интервалах blanking, per-frame BTA отключён.
Приложение меняет вертикальные/горизонтальные полосы примерно раз в 5 секунд.
Для смены ориентации host кратко переводится в standby; состояние PLL и панели
сохраняется. Ошибки снимаются **перед** standby, чтобы перезапуск host не скрыл их.
USB-консоль блокирующая: без читающего хоста цикл приложения может остановиться,
но уже запущенный аппаратный видеопоток продолжает работать.

## Аппаратная проверка 2026-11-04

Образ **17520 байт** записан по 0x2000 и запущен на подключённой rev 1.3.
Проверены начальная версия и версия с переключением VPG через standby:

- Host version `0x3134312A`, PHY PLL locked, stop state обеих data lanes
  и clock lane подтверждён (`PHY_STATUS=0x15BD` до видео).
- Все команды прошли без таймаутов; command и payload TX FIFO опустели.
- DCS `0x04` вернул **00 00 00**: это результат чтения, **не подтверждённый
  уникальный ID JD9165**. Название панели пока основано на старом проекте.
- DCS `0x0A` после инициализации вернул **0x14**.
- Video mode и VPG включены, ориентация переключается по логам. Пользователь визуально подтвердил оба вида полос.
- GT911 продолжил опрос, errors=0; RTC читается.
- При первоначальном переключении VPG на ходу появлялся
  `INT_ST1=0x00080000`: `DPI_BUFF_PLD_UNDER` (underrun входного DPI buffer),
  включая повторные события в длинном прогоне. После смены ориентации через
  standby в финальном прогоне **девять снимков до переключения, за 40 секунд**
  дали errors0=0/errors1=0; GT911 достиг 4597 кадров, errors=0. Это ограниченная
  проверка, а не доказательство отсутствия редких событий. Пользователь подтвердил видимые вертикальные и горизонтальные полосы;
  также наблюдал мелькавший зелёный фон. Отдельная зелёная заливка приложением
  не задаётся, причина этого переходного изображения пока не установлена.

## Текущий режим: BER

По запросу пользователя включён постоянный `Pattern::Ber`: VPG_EN=1,
VPG_MODE=1, VPG_ORIENTATION=0. Автоматическое переключение полос и периодический
перезапуск host отключены. Тайминги, RGB565, PHY и подсветка сохранены.
Образ 16368 байт. Это визуальный тестовый шаблон; численный BER не измеряется.
Лог запуска: `target/display-ber.log`.

## Подсветка: LEDC 20 кГц

`hal::ledc::Pwm<PIN>` потребляет `gpio::Output<PIN>`; после этого исходным
GPIO нельзя отдельно управлять через прежний объект. Конструктор `unsafe`:
требует эксклюзивного владения **всем LEDC**, потому что сбрасывает модуль
и задаёт общий источник тактирования. В текущем варианте используются
low-speed channel 1, timer 1, GPIO23, matrix signal 127.

```rust
let pin = unsafe { hal::gpio::Output::<23>::new_low() };
let mut backlight = unsafe { hal::ledc::Pwm::new(pin) }; // Initially off.
backlight.set_brightness(65); // 0..=100%; values above 100 saturate.
backlight.set_duty(512);      // Raw 0..=1024; 512 = 50%.
```

LEDC `0x500D3000`, CH1 `+0x14`, TIMER1 `+0xA8`; APB clock
`0x500E6020` bit 0, reset `0x500E60C4` bit 29, functional clock/mux
`0x500E609C` bits 2/1:0. Источник — XTAL 40 МГц, разрешение 10 бит,
делитель Q8 = **500** (1.953125): `40_000_000 * 256 / (500 * 1024) = 20_000`.
PLL для PWM не требуется. DUTY хранится со сдвигом на 4; применяется через
DUTY_START и channel PARA_UP. Gamma RAM канала очищается; одна запись с нулевым
scale загружает duty без аппаратного fade. Изменение применяется асинхронно
на следующих PWM-циклах. Проценты округляются к ближайшему duty; это линейная
скважность, а не перцептивная или измеренная оптическая яркость.

При первоначальной проверке приложение один раз проходило 0/25/50/75/100/65%, с задержкой 500 мс
и выборкой GPIO_IN 100 мс на каждом уровне. После того теста оставалось 65% (duty=666).
По запросу пользователя текущий запуск сразу задаёт **5% (duty=51)**,
без перебора уровней; выполняется только диагностическая выборка этого уровня.
BER-шаблон сохраняется. Опрос touch начинается после этой стартовой проверки.

На подключённой плате 2026-11-04 получено:

| Задано | DUTY_R | Восходящих фронтов / 100 мс | Доля high по выборкам GPIO_IN |
|---|---:|---:|---:|
| 0% | 0 | 0 | 0% |
| 25% | 256 | 1999 | ~25% |
| 50% | 512 | 2000 | 50% |
| 75% | 768 | 2000 | ~75% |
| 100% | 1024 | 0 | 100% |

100% — постоянный high, 0% — постоянный low; ноль фронтов там ожидаем.
Один фронт погрешности окна 100 мс соответствует 10 Гц. Проверка относительная:
SYSTIMER и LEDC используют один кварц; абсолютная точность кварца, форма
сигнала и яркость светодиодов внешними приборами не измерялись. Работа на
малых уровнях и отсутствие слышимого шума пользователем пока не подтверждены.

Лог: `target/backlight-20khz.log`. Образ **18016 байт**, прошит и запущен.
Release/clippy/fmt проходят, 8 host-тестов прежних драйверов проходят.
Источники: ESP-IDF v6.1 `esp_hal_ledc/esp32p4/include/hal/ledc_ll.h`,
`esp_driver_ledc/src/ledc.c`, регистры `hw_ver1/soc/ledc_reg.h`.

## Документация контроллера

Исследованы даташиты JADARD и модульный документ из пакета платы:
[возможности JD9165 и план графического тракта](jd9165.md). Полной GRAM нет;
модульный документ указывает JD9165BA-DS, а найденный полный manual — A-A.
Ранее неопределённый вариант хранения кадра внутри панели исключён для
документированного семейства. Доступен отдельный BIST панели и описан
приёмный счётчик ошибок DCS 05h; эти функции на экземпляре ещё не испытаны.

## Публичный API и расширенные проверки 2026-11-05

Управление перенесено в `devices::jd9165::Display`: DSI, LCD RESET и PWM
владеются одним объектом. Реализованы статус/ошибки, pattern, brightness,
inversion, mirror, RGB/BGR, display on/off, idle/idle color, black/white
override, sleep/wake, soft/hard reset и TE-конфигурация. Подтверждено
сохранение пользовательских настроек при обоих сбросах. Runtime DCS теперь
использует LP/BTA в vertical blanking; обычные чтения не останавливают видео.
Проверены VPG RGB565 на 650/750 Mbps и RGB888 на 750 Mbps, затем возврат
к RGB565/550. Девять снимков host по этим режимам без ошибок, четыре
приёмных счётчика — ноль. Образ 26160 байт.

Scanline 45h остаётся нестабильной диагностической пробой (некорректируемая
ECC ответа); следующий нормальный обмен восстанавливается. BIST панели
не предоставляется без подтверждённого способа включения BA. Текущее
состояние: BER / RGB565 / 550 Mbps / 5%. API, команды и точные границы
проверки: [display-api.md](display-api.md).
