# HP1, LP и расширения CPU — 2026-11-14

База перед экспериментами: `bc27540` — постоянный Ethernet web, фоновые
часы/будильник и ручное освобождение файлов/кешей без остановки веба.

## Порядок освоения

1. HP1: старт, отдельный стек, обмен заданиями, межъядерные IRQ, владение
   памятью, кеши и проверка параллельной нагрузки.
2. LP: собственный код в LP SRAM, обмен с HP, сон/пробуждение LP,
   таймеры и затем сон HP с сохранением работы LP.
3. Расширения Espressif: PIE/SIMD, аппаратные циклы, измерения и обёртки
   для Rust. Модели, wakeword и детекция лиц пока вне реализации.
4. Аппаратные JPEG decode/encode, PPA и DMA2D. Фоторамка в админке позже;
   сейчас нужны драйверы и проверка аппаратных возможностей.

## Первый HP1 probe

`./scripts/image.sh --features multicore-lab`

`src/multicore_lab.rs` — изолированный лабораторный тест до запуска дисплея,
SD и сети. В обычный образ не входит. На старте лабораторного образа есть
пауза 3 секунды для подключения USB-монитора.

Последовательность из локального ESP-IDF v6.1:

- PMU CPU_SW_STALL, HP1 code `0xff` — снять stall;
- HP_SYS_CLKRST SOC_CLK_CTRL0 bit4 — тактирование HP1;
- HP_RST_EN0 bit8 — снять global reset HP1;
- ROM `ets_set_appcpu_boot_addr`, `0x4fc000a8` — адрес нашего входа.

Ядро получает собственный статический стек 8 КиБ, прямой mtvec с записью
mcause/mepc/mtval; IRQ выключены. Код HP1 пока полностью на ассемблере:
не требует gp, TLS, FPU и сохранения векторных регистров.
Оба ядра обращаются к mailbox через uncached alias SRAM `0x8ff...`.
Публикация ответа упорядочена fence; HP0 использует Release/Acquire.
Первый тест идёт при выключенных L1 и L2=0. Это ещё не доказательство
работы mailbox при D-cache ON, конкурентных DMA и переключении кешей.

На плате rev1.3 подтверждено повторными прошивками:

- `mhartid=1`, `misa=0x40901125`;
- 1000 заданий, каждое — 256 итераций xorshift32; все ответы проверены HP0;
- около 92 мс на полный обмен и проверку, включая ожидание старта;
  это не оценка ускорения параллельных вычислений;
- `parked=true`, `guard=true`, исключений нет;
- после теста нормально запускаются LCD, SD и постоянный Ethernet web.

После команды остановки HP1 подтверждает прекращение работы и входит в WFI,
HP0 устанавливает stall code `0x86`. Память стека/mailbox остаётся
зарезервированной даже при timeout. Флаг CORESTALLED не используется как
доказательство парковки: IDF предупреждает о ненадёжности флага при WFI на
ранних ревизиях. Это одноразовый boot probe, не API перезапуска ядра.

Следующий шаг HP1: выделить проверенную последовательность в HAL, очередь
с единственным владельцем, межъядерное уведомление и тесты с L1/DMA.
Периферию, USB-консоль и аллокаторы второму ядру сейчас не передаём.

## LP memory и первый probe

`./scripts/image.sh --features multicore-lab,lp-lab`

`src/lp_lab.rs`: отдельный integer-only blob, копируемый HP в LP SRAM.
Код позиционно независим относительно места хранения в HP образе; переходы
внутри относительные, адреса LP данных/стека явные. Проверять дизассемблер
после изменения blob, особенно положение trap-вектора +0x200.

Используем только `0x50109000..0x5010a000`: код, mailbox и отдельный стек
1 КиБ. Низ LP RAM не трогаем. Верх LP RAM с `0x5010fa80` занят стеком/данными
LP ROM: считать все 32 КиБ свободной памятью приложения нельзя.

Цель probe: 3 входа через PMU HP wake, 100 проверенных ответов за каждый вход,
затем запрос сна LP. Сон HP/всей платы, энергопотребление и LP-периферия
этим тестом не проверяются. Настройки/память LP могут переживать reset HP;
нельзя считать soft reset платы эквивалентом снятия питания.

## ISA: что подтверждено, что ещё проверить

HP1 `misa=0x40901125` сообщает RV32 и A/C/F/I/M/U/X. X указывает наличие
нестандартных расширений, но сам по себе не описывает их инструкции.
Обозначение RV23 не используем как подтверждённый ISA-профиль этой платы.
Текущий Rust target остаётся `riscv32imafc-unknown-none-elf`.

В IDF P4 soc_caps: PIE, SIMD, hardware loops, предпочтительное выравнивание
SIMD 16 байт. Комментарий IDF: PIE assembly поддерживается GCC. Доступность
мнемоник/кодирования через наш LLVM ещё не проверена; фреймворк не добавляем.
PIE-state CSR `0x7f2`: OFF/Initial/Clean/Dirty. Нужен явный учёт состояния
PIE и аппаратных циклов при прерываниях/смене задач. Нынешний integer-only
trap frame сам по себе эти регистры не сохраняет. Для HWLOOP IDF также
отмечает erratum: окончание цикла не переводит состояние в Dirty.

До реального использования: карта инструкций и ограничений rev1.3,
поддержка ассемблера, скалярный эталон, проверка выравнивания/границ,
замеры циклов и корректность при IRQ. Наличие 128-битных SIMD-операций не
делает ISA стандартным RVV и не означает 128-битную скалярную арифметику.

## Результат LP на плате

После подтверждения/очистки HP_SW_TRIGGER получены:
`bytes=560 boots=3/3 jobs=300/300 hart=0 misa=40101105 sp=5010a000 guard=true`.
Три входа показывают возврат через reset-entry после сна LP; данные mailbox
между входами сохранились. Trap mailbox остался нулевым. Отдельное наблюдение
аппаратного debug PC показало адрес WFI внутри нашего LP blob.

Первоначальная проба без явного подтверждения HP_SW_TRIGGER не прошла:
HP не увидел входа нового задания; debug PC находился в WFI нашего кода.
Добавлено очищение сохранённого события до загрузки и на каждом входе LP,
как это делает IDF в `ulp_lp_core_update_wakeup_cause`. Больше нельзя
принимать изменение boot-address за достаточное условие перезапуска LP.
Ни расход энергии, ни сон HP этим не измерены.
