# Guition JC1060P470C — аппаратная справка

Составлено 2026-11-04 по двум распакованным проектам: `old/esp-32-p4-v1.3` (далее **display**) и `old/esp32-p4-voice-device` (далее **voice**).

Все номера GPIO относятся к **ESP32-P4**, а не к контактам разъёмов. Нумерация контактов FPC и внешних колодок в архивах не найдена. Проверка физической платы при подготовке этого файла не проводилась.

Уровни доказательств:

- **Код** — назначение непосредственно присутствует в исходниках или конфигурации из архива.
- **Опись** — сведения из сохранённых `hardware.yaml`; там могут быть ссылки на прежние испытания, заводские логи и фото. Сами эти логи, фото платы и BSP в данных архивах не найдены, поэтому повторно подтвердить результаты невозможно.
- **Неизвестно** — данных недостаточно; предполагаемые назначения не подставлены.

## I²C: общая шина управления

**I2C_NUM_1, SDA GPIO7, SCL GPIO8.** В voice установлено **100 кГц**, в display для touch — **400 кГц**. Эти частоты отражают настройки прошивок; работа всей периферии на 400 кГц не проверена в рамках этой работы. voice включает внутренние подтяжки; номиналы внешних резисторов неизвестны.

Все адреса в таблице — **7-битные**.

| Адрес | Устройство | Регистры / идентификация |
|---|---|---|
| `0x18` | ES8311 | Регистры `0xFD`, `0xFE`: ожидается `0x83`, `0x11`; версия `0xFF`, по описи `0x01` |
| `0x32` | RX8025T | voice читает `0x00…0x0F`; время `0x00…0x06`, управление `0x0E`, `0x0F` |
| `0x36` | Камера OV02C10 по описи | Чтение `0x300A…0x300B`; по описи ID `0x5602` |
| `0x5D` | GT911, основной адрес | Product ID `0x8140`, ожидается `39 31 31 00` / `911\0` |
| `0x14` | Альтернативный ответ GT911 по описи voice | В описи сообщается такой же Product ID; не считать отдельной микросхемой |

**Исправление старой описи:** в `display/hardware.yaml` ES8311 ошибочно помечен как 7-битный `0x30`. В voice прямые обращения идут на `0x18`; значение `.addr = 0x30` передаётся только в `audio_codec_new_i2c_ctrl`, принимающий 8-битный адрес и сдвигающий его вправо. Это явно объяснено в `audio_voice.c`.

Touch, кодек, RTC и камера должны пользоваться одним экземпляром общей шины. Не устанавливать независимые конкурирующие драйверы на I2C1.

## Экран JD9165

| Параметр | Настройка обоих проектов |
|---|---|
| Разрешение | 1024×600, альбомная ориентация |
| Интерфейс | MIPI-DSI, bus 0, **2 data lanes**, 550 Мбит/с на линию |
| Команды | DBI поверх DSI, virtual channel 0, команды и параметры по 8 бит |
| Видеопоток | DPI, virtual channel 0, pixel clock **50 МГц** |
| Формат framebuffer | RGB565, 16 бит/пиксель, порядок RGB |
| Буферы | 2 × 1 228 800 байт = 2 457 600 байт |
| Горизонтальные интервалы | back porch 136, sync pulse 20, front porch 160 |
| Вертикальные интервалы | back porch 12, sync pulse 2, front porch 20 |
| Частота кадров | Расчёт по таймингам ≈58,85 Гц; в старой описи указано измерение 58,875 Гц |
| Питание MIPI PHY | LDO channel 3, **2500 мВ** |
| Сброс | GPIO27 |
| Подсветка | GPIO23, LEDC low speed, timer 1, channel 1, **5 кГц**, **10 бит** |

Яркость задаётся duty `percent × 1023 / 100`: увеличение duty повышает установленную яркость. Стартовое значение display — 5%, voice — 65%; это программная настройка. Используется DMA2D; display также содержит PPA-композитор.

Полная последовательность инициализации JD9165 сохранена в обоих `display*.c`; заканчивается командами `0x11` с задержкой 120 мс и `0x29` с задержкой 50 мс. При переносе драйвера нужно сохранить эту таблицу. Номера контактов дифференциальных пар DSI и FPC в исходниках не указаны.

## Сенсор GT911

- I²C1 на GPIO7/8, основной адрес `0x5D`.
- Адрес регистра передаётся двумя байтами, старший первым.
- `0x814E` — статус: bit 7 означает готовые данные, младшие 4 бита — число касаний.
- `0x814F` — первая точка: ID, X low/high, Y low/high и остальные байты записи.
- После обработки прошивка записывает `0` в `0x814E`.
- Опрос каждые **10 мс**; код использует первую точку. Наличие нескольких касаний в статусе не означает поддержку multitouch на уровне приложения.
- Координаты используются напрямую в пространстве 1024×600.
- GPIO RESET и INT не назначены. Старая опись ссылается на BSP, где они обозначены как NC; фактическая разводка не восстановлена.

## Звук и микрофон

ES8311 управляется по I²C, звук передаётся по **Philips I²S1**. P4 — master, кодек — slave, используется MCLK. В voice создаётся пара TX/RX; чтение микрофона выполняется через RX. Тактовые сигналы не инвертируются.

| Сигнал ES8311 | GPIO P4 |
|---|---:|
| MCLK | 13 |
| BCLK / SCLK | 12 |
| LRCLK / WS | 10 |
| Вход цифрового аудио кодека (P4 DOUT) | 9 |
| Выход ADC кодека (P4 DIN) | 48 |
| Управление усилителем динамика по описи | 20 |

Микрофон **аналоговый**, `.digital_mic = false`. Запись voice: **16 кГц, mono, signed PCM16 LE**, входное усиление **24 дБ**. WAV: PCM, заголовок 44 байта, byte rate 32 000, block align 2. Максимальная запись 6 секунд занимает 192 000 байт PCM в PSRAM и не требует SD-карты. Промежуточное чтение I²S идёт во внутренний буфер; даже при `ESP_ERR_TIMEOUT` могут быть полезные `bytes_read`.

Параметры модели усиления в коде: `pa_voltage = 5.0`, `codec_dac_voltage = 3.3`; это значения для библиотеки, а не измерение питающих шин. В voice `.pa_pin = -1`: GPIO20 не переключается, воспроизведение через динамик этим кодом не подтверждено. Backend не поддерживает API mute входа. По описи прежние тесты давали ненулевой сигнал и иногда насыщение на 24 дБ; первичных записей в архивах нет.

## ESP32-C6 и беспроводная связь

По описи: **ESP-Hosted SDIO**, host P4, slave C6, **slot 1**, 4 бита, **40 МГц**. CLK=18, CMD=19, D0=14, D1=15, D2=16, D3=17, RESET=54. Bluetooth HCI over SDIO отмечен в прежнем заводском логе.

voice реально содержит вызовы `esp_hosted_init()` и `esp_hosted_connect_to_slave()`, Wi-Fi station, сканирование, подключение и получение IP. Пины SDIO и частота в коде приложения не заданы; сохранённого `voice/sdkconfig` и исходников компонента ESP-Hosted нет, поэтому приведённую конфигурацию нельзя считать проверенной по его сборке. Прошивка C6 и порядок её обновления в архивах отсутствуют. Поддержка Bluetooth в приложении не реализована.

## microSD / TF

По обеим описям: **SDMMC slot 0, 4-bit**. D0=39, D1=40, D2=41, D3=42, CLK=43, CMD=44. Card detect и write protect не назначены.

Альтернатива SDSPI из описи: MISO=39, MOSI=44, CLK=43, CS=42. Это альтернативное использование тех же линий, а не второй независимый интерфейс. Частота, питание и номиналы подтяжек не восстановлены. Опись ссылается на прежнюю запись `/sdcard/mic.wav`; в имеющихся приложениях драйвер карты не реализован.

## USB и консоль

В display реализован **USB 2.0 High-Speed OTG device**, TinyUSB `TINYUSB_PORT_HIGH_SPEED_0`, vendor-specific bulk:

| Параметр | Значение |
|---|---|
| VID:PID | `303A:4041` — значения этой прошивки |
| Manufacturer / product | Guition / Guition P4 Remote Display |
| Serial string | `P4-REMOTE` — фиксированная строка |
| Интерфейс 0 | GID1, OUT `0x02`, IN `0x82` |
| Интерфейс 1 | GID2, OUT `0x04`, IN `0x84` |
| Bulk max packet size | HS 512 байт; в FS-дескрипторе 64 байта |
| Заявленный ток в дескрипторе | 100 мА; это не измеренное потребление платы |

GID1/GID2 — прикладные протоколы удалённого дисплея: команды рисования, передачи данных и события touch. Это не CDC/UART. Детали сохранены в `display/main/protocol*.c`, `display/docs/gid2-compositor.md` и host SDK.

Описи называют два Type-C: High-speed и Full-speed. Для FS указаны D−=GPIO19, D+=GPIO20, что пересекается с SDIO CMD и PA enable. Комментарий в voice также связывает GPIO20 с USB Serial/JTAG. Одновременно старые заметки в описях приписывают путь Serial/JTAG разъёму High-speed. **Эти описания неоднозначны: фактическое соответствие разъёмов, PHY и GPIO по архивам не установлено.** FS-дескриптор TinyUSB сам по себе не доказывает разводку второго разъёма. До проверки схемы не использовать GPIO19/20 одновременно для перечисленных функций.

Консоль display: **UART0, 115200 бод**, дополнительно включён USB Serial/JTAG. По описи UART использует GPIO37/38, но направление TX/RX не приведено. Соответствие внешним разъёмам UART/UART1 неизвестно.

## Камера, RTC и Ethernet

**Камера:** voice читает два байта ID по I²C `0x36`, начиная с `0x300A`; опись voice сообщает OV02C10 / `0x5602`. Предполагаемый видеотранспорт по описи — MIPI-CSI. GPIO reset, power-down, XCLK, питание, число линий и порядок контактов FPC неизвестны. Упоминание `BSP_CAPS_CAMERA=0` в описи относится к старому BSP и не опровергает наличие датчика; захват кадров в архивах не реализован.

**RTC:** voice читает RX8025T на `0x32`; опись сообщает VLF=0, VDET=0 и сохранение времени при перезапуске. Исходного тестового лога нет. INT/выходы RTC и схема батареи неизвестны. Часы интерфейса voice синхронизируются через SNTP; наличие RTC не означает, что приложение использует его как источник времени.

**Ethernet:** известны лишь упоминания RJ45 и 100 Мбит/с в описях. PHY, MDC/MDIO, RMII-сигналы, reset, clock и адрес PHY не найдены. Драйвера Ethernet в приложениях нет.

## Различия конфигураций и ограничения переноса

1. **Flash DIO/QIO:** display defaults задаёт QIO/80 МГц, но сохранённый `sdkconfig` противоречив: `CONFIG_ESPTOOLPY_FLASHMODE_QIO=y` при строке `CONFIG_ESPTOOLPY_FLASHMODE="dio"`. Более новая опись voice сообщает успешную работу DIO/80 МГц и оставляет QIO неподтверждённым. Фактический режим следует проверять по новой сборке и boot log.
2. **Адрес ES8311:** использовать 7-битный `0x18`; `0x30` допустим только в API с явно 8-битным адресом.
3. **I²C:** voice 100 кГц, display 400 кГц для touch. Создавать одну общую шину.
4. **USB/GPIO19/20:** карта из описей содержит конфликт и неоднозначность разъёмов; PA в voice намеренно отключён.
5. **Память:** в `display/main/protocol_v2.c` INFO содержит жёстко заданное `0x00200000` (2 МиБ) с комментарием «confirmed PSRAM bytes». Это не измерение объёма PSRAM и расходится с 32 МиБ в аппаратных описях; определять реальный объём через runtime API/boot log.
6. **SDK:** опись display указывает ESP-IDF 5.5.3; README и defaults voice — ESP-IDF 6.1.0. Не переносить конфигурацию между версиями без проверки.
7. **Проверенность:** код display реализует LCD/touch/USB; voice — LCD/touch, диагностику I²C, ESP-Hosted Wi-Fi и запись/отправку аудио с WakeNet. Наличие кода не подтверждает успешный запуск на текущей плате. По описи voice сквозная проверка содержимого записи и ответа сервера оставалась незавершённой.

## Прямой запуск собственного Rust runtime

2026-11-04 подтверждён запуск без программного второго загрузчика: ROM `esp32p4-eco2-20240710` читает наш образ с flash `0x2000`, загружает в HP TCM `0x30100000` и передаёт туда управление. В ROM-логе режим `SPI_FAST_FLASH_BOOT`; затем приложение выдаёт USB-маркер `P4 rev1.3: ROM -> Rust OK`.

HP TCM: 8 КиБ, `0x30100000…0x30101FFF`; в первом минимальном runtime стек размещался на верхней границе. В текущем runtime стек/BSS перенесены в SRAM `0x4FF00000…0x4FF03FFF` (см. раздел I²C ниже). Для устойчивой работы с прямым стартом отключены LP RTC WDT, super-watchdog и MWDT обоих timer groups. У MWDT отдельно снимается `FLASHBOOT_MOD_EN` (bit 14), конфигурация применяется через `CONF_UPDATE_EN` (bit 22); одного снятия `WDT_EN` недостаточно.

USB Serial/JTAG FIFO для этой ревизии: `0x500D2000`, EP1 config `0x500D2004`, data-free bit 1, WR_DONE bit 0. Linux-монитор `scripts/monitor.py` освобождает DTR/RTS. Исходный bootloader по `0x2000` заменён нашим образом; для возврата ассистента нужен полный сохранённый дамп.

Подробные особенности сбросов и повторного запуска, расшифровка ROM-лога и последовательность отключения watchdog: [docs/boot.md](docs/boot.md).
