# Flashbox

Локальный файловый менеджер ESP32-P4: HTML/CSS/Vanilla JS, системные шрифты,
SVG-иконки внутри страницы, без фреймворков, npm и обязательного CDN.
Текущий index.html: **84884 байт**, хранится только на SD.
Дополнительный photo-tools.js загружается с SD только для подготовки фотографий.

## Рабочий экран

- Поиск и сортировка выполняются в браузере по уже полученному каталогу.
  Папки всегда первыми, имена сравниваются с учётом русского языка и чисел.
- Плюс загружает оригиналы. В ⋮: новая папка, загрузка папки целиком,
  запуск фоторамки и отдельная загрузка фото с подготовкой JPEG.
- Лупа показывает/скрывает поиск, по умолчанию он скрыт. Сортировка переключается
  кликом на «Имя»/«Размер», стрелка показывает выбранное направление.
- Файлы и папки с точки по умолчанию скрыты; глаз включает показ и цвет primary.
  Фильтрация только в браузере, API возвращает полный каталог.
- Пустая область операций не занимает места. Завершение операции — toast,
  непросмотренные ошибки устройства — страницы по5 с диагностикой и подтверждением.
- Дата скрыта: API не передаёт её. Длинные имена и пути переносятся.
- File chooser открывается настоящими кнопками и доступен с клавиатуры.
  Каталоги/хлебные крошки — ссылки; после перехода focus попадает в рабочий заголовок.
- Ошибка чтения отделена от пустого списка и имеет действие «Повторить».
- Неудавшиеся загрузки остаются в списке с именами/причинами. По кнопке повторяются
  только они, с сохранением исходной папки назначения и опции подготовки.
- Светлая/тёмная темы следуют системной настройке. Подписи имеют контраст>4,5:1;
  виден focus, учитывается reduced-motion. Нет обязательных анимаций/размытий.

## Текстовый редактор

«Редактировать» в меню файла открывает браузерный textarea, до1МиБ UTF-8.
«Сохранить» и «Сохранить как» используют обычные PUT/rename/delete запросы,
без новых методов платы. Детали: [text-editor.md](../docs/text-editor.md).
Настройка открываемых по клику расширений пока не добавлялась.

## Демо и установка

`demo.html` содержит тот же общий UI с in-memory каталогом/XHR-адаптером:
операции не записываются на устройство. Для проверки локально достаточно HTTP-сервера.
Веб хранится только на SD в `/www`. Встроенной страницы и gzip fallback нет.

Размещение на SD: `python3 scripts/install-web.py --replace`. Предыдущий index
сохраняется как /www/B*.BAK, временная страница и публикация сверяются readback.
Интерфейс из /www обновляется без перезапуска платы. Встроенного /flash больше нет;
аварийное восстановление — DELETE, затем PUT через /fs/www/.

Проверки из корня: `node tests/frontend-directory.mjs`, остальные
`tests/frontend-*.mjs` и `tests/photo-tools.mjs` — без npm.

## Очередь и текущие ограничения

Выбор файлов и drag-and-drop добавляют задания в одну очередь; одновременно
выполняется только один PUT. У задания сохраняется папка назначения на момент
добавления: переход в другую папку не перенаправляет ожидающие файлы. Можно
добавить файлы и во время загрузки, и во время финального обновления каталога.
Ошибка одного файла не отменяет оставшуюся очередь; автоматического retry нет.

Первый backend использует create-new: существующий файл не перезаписывается,
ожидается HTTP 409. Demo учитывает эту семантику и регистронезависимость имён.
Новые имена поддерживают Unicode, пробелы и FAT LFN: до 255 UTF-16 units
на компонент и 768 UTF-8 байт на путь; неверное имя отклоняется до отправки тела.
Предел FAT32 — 4 ГиБ − 1 байт. Имена не обрезаются и не переименовываются молча.
LFN и короткие aliases создаёт новый async FAT backend.

На борде работает собственный bounded TCP/HTTP backend: страница из `/www/index.html` на SD,
GET/HEAD файлов, список и потоковый PUT на SD. Запуск и ограничения —
[docs/web.md](../docs/web.md). FAT32 публикует файл только после finish;
обрыв при здоровом носителе вызывает abort. I/O failure оставляет dirty volume.

Проверки без npm: `node tests/frontend-uploads.mjs` из корня проекта.

## HTTP API

Фронтенд рассчитан на три простых операции:

| Метод | Endpoint           | Назначение             |
| ----- | ------------------ | ---------------------- |
| `GET` | `/api/list?path=/` | Получить список файлов |
| `GET` | `/fs/name.bin`     | Скачать файл           |
| `PUT` | `/fs/name.bin`     | Загрузить файл         |

Формат ответа на запрос каталога:

```

{
  "entries": [
    {
      "name": "documents",
      "dir": true,
      "modified": "2026-11-07T12:00:00Z"
    },
    {
      "name": "firmware.bin",
      "dir": false,
      "size": 1874320,
      "modified": "2026-11-07T13:40:00Z"
    }
  ]
}

```

И тот же API сразу подходит для `curl` (IP взять из WEB READY; mDNS пока нет):

```

# Список
curl "http://192.168.1.167/api/list?path=/"

# Загрузка
curl -T firmware.bin http://192.168.1.167/fs/firmware.bin

# Скачивание
curl -o firmware.bin http://192.168.1.167/fs/firmware.bin

```

## Почему именно PUT

Я специально не использовал `multipart/form-data`. Браузер передаёт `File` непосредственно как тело HTTP-запроса. На стороне ESP32 можно читать его порциями и сразу писать на флешку, не буферизуя целиком в RAM.

Страница отдаётся с SD как обычный UTF-8 HTML; встроенная сжатая копия удалена.

В перспективе WebDAV выбранный URL `/fs/...` можно сохранить: `GET` и `PUT` уже совпадают по смыслу, останется добавить `PROPFIND`, `MKCOL` и остальные нужные методы.

Единственное архитектурное замечание: проверку путей и прав доступа нужно делать на ESP32, а не в JavaScript. Пока это простой HTTP, но у нас ограничен доступ доверенной локальной сетью поэтому пофик на секюрность.

Получился интерфейс с расчётом именно на embedded HTTP-сервер, а не уменьшенная копия тяжёлого SPA.


## Обновление файловой панели

Теперь доступны создание/загрузка папок, рекурсивное удаление через
последовательные запросы и переименование в пределах папки. Действия строки
собраны в кнопку `⋮` с popover; имя файла открывает просмотр, «Скачать»
использует `?download=1`. Поддерживаются длинные Unicode-имена.
Добавлен пульт состояния/яркости и текстовый буфер1024 байта UTF-8.
Актуальный полный API и ограничения: [docs/web.md](../docs/web.md).

`demo.html` использует тот же UI с отдельным in-memory адаптером; состояние
демо не сохраняется. Проверки: `node tests/frontend-uploads.mjs` и
`node tests/frontend-files.mjs`. Веб выкладывается отдельно от прошивки.
Сборщик прошивки всё равно сам сжимает актуальный `index.html`.

### Индикация передачи (2026-11-14)

PUT файлов использует XMLHttpRequest с upload.onprogress: процент, байты,
скорость в МиБ/с, ориентировочное оставшееся время, очередь и отмена всей очереди.
Передача остаётся последовательной. Обновление каталога/переход в папку не
убирает отдельный блок прогресса. На 100% ждём HTTP-подтверждения сохранения;
ошибки сети/HTTP и отсутствие новых данных показаны отдельно. Автоматических
повторов и короткого таймаута для гигабайтных файлов нет.

При отмене очередь очищается и XHR прерывается. Затем HEAD проверяет, завершила
ли борда удаление незавершённого файла (409: писатель ещё занят, 404: файла нет).
Если файл уже присутствует/нет связи, интерфейс сообщает это без обещания удаления.
При попытке уйти со страницы во время загрузки браузер предупреждает о прерывании.
Прогресс означает переданные браузером байты, не отдельный счётчик SD durability.

Подход сверили с reference/tab5-devos/components/devos_fileshare/fileshare_page.c;
готовая страница DevOS не переносилась: endpoints и API каталогов у нас другие.
Demo использует тот же UI и локальный XHR-адаптер без записи на устройство.
Проверки: node tests/frontend-upload-progress.mjs (включая скорость/ETA,
ожидание подтверждения, отмену очереди и очистку таймеров), прежние frontend tests.

На плате проверено в настоящем headless Chromium: XHR4MiB+13B, живые события
прогресса (36,3%,1,34МиБ/с в контрольной точке), полное совпадение содержимого,
подтверждение сохранения только после ответа сервера. Второй4MiB PUT отменён
кнопкой: дождались исчезновения writer, незавершённый файл удалён, root совпал.
Превью: target/upload-ui-preview.png; лог: target/frontend-checks/p4-ui-live.log.

Страница на SD устанавливается `python3 scripts/install-web.py`; [правила установки и fallback](../docs/web-sd-page.md).

Аварийное восстановление: DELETE `/fs/www/index.html`, затем PUT туда же.

В «Управление бордой» добавлена ручная очистка файлов/кешей. Подтверждение
приходит после завершения операции; незаконченные передачи отменяются, веб
остаётся доступен. При активном будильнике — отказ до его остановки.

## Фоторамка

Кнопка в «Ещё» открывает native dialog для текущей папки: интервал, срок
работы или постоянно, вписать/обрезать, mirror/alternate180/wipe/slide.
Пока запущена, доступна остановка из любой папки. Состояние опрашивается
раз в2с; перезагрузка браузера не прекращает показ. Только явный POST
запускает режим. На плате часы скрыты; будильник прерывает фоторамку.
См. [photoframe.md](../docs/photoframe.md). Проверка UI:
`node tests/frontend-photoframe.mjs`. В demo изменения остаются in-memory.
